# 顶栏历史路由标签设计规格

## 1. 背景与目标

当前顶栏左侧仅展示“当前模块 + 本地单人空间”，占用了固定空间，却不能帮助用户在多个工作页面之间快速返回。本次将该区域改造成紧凑的历史路由标签条，复用 `treasure-box` 已验证的路由同步、去重、持久化和关闭后邻近跳转算法，但不迁移其视觉样式。

目标：

- 在不挤压全局搜索和右侧操作区的前提下，提供可见、可切换、可关闭的访问历史。
- 适配工作台现有浅色视觉、窄顶栏和 macOS Dock 布局。
- 防止筛选参数、内部页签参数制造大量重复标签。
- 按登录用户隔离历史记录，避免切换账号后串用记录。

## 2. 范围

### 2.1 本期包含

- 当前路由自动加入历史标签。
- 标签点击切换、关闭、关闭当前标签后跳转相邻标签。
- “工作台”固定且不可关闭。
- 当前标签、最近标签优先展示，其余标签进入“+N”溢出菜单。
- 溢出菜单支持打开、关闭单项、关闭其他标签。
- 标签状态按用户持久化到 `localStorage`。
- 动态项目、员工等详情页生成稳定路由键和可读标题。
- 鼠标、键盘和屏幕阅读器可访问交互。

### 2.2 本期不包含

- 页面组件缓存或类似浏览器 Back/Forward Cache 的状态快照。
- 跨设备、多浏览器同步历史标签。
- 标签拖拽排序。
- 恢复每个页面的滚动位置、未提交表单或弹窗状态。
- 复制 `treasure-box` 的主题、颜色、箭头和标签样式。

## 3. 交互设计

### 3.1 顶栏结构

顶栏继续使用三段响应式布局：

1. 左侧：产品标识、分隔线、历史路由标签。
2. 中间：全局搜索入口。
3. 右侧：新建、最近访问、通知、设置和账号菜单。

历史标签区域使用 `min-width: 0` 和弹性宽度，只消费左侧可用空间，不改变搜索区与操作区的最小可用宽度。

### 3.2 标签展示

- 当前标签始终可见，使用浅蓝背景、蓝色文字和底部细指示线。
- 最近访问的其他标签按现有顺序填充剩余空间。
- 普通标签在默认状态下不显示关闭图标，悬停或键盘聚焦时显示，减少视觉噪声。
- 标签标题单行省略，完整标题通过原生 tooltip 或可访问描述提供。
- “工作台”标签固定在第一位，不显示关闭按钮。
- 空间不足时，不展示的标签计入“+N”按钮；点击后打开紧凑下拉菜单。

### 3.3 溢出菜单

菜单按标签顺序展示所有当前不可见的历史记录。每项包含标题、当前状态和关闭操作，并支持：

- 点击标题打开目标地址。
- 关闭单个标签。
- 关闭其他标签，仅保留工作台和当前标签。

菜单不提供“关闭全部”，因为工作台必须永久保留。

### 3.4 关闭规则

- 工作台不可关闭。
- 关闭非当前标签时保持当前页面不变。
- 关闭当前标签时优先打开其左侧相邻标签；没有左侧标签时打开右侧；最后始终可以回到工作台。
- 当前页因权限撤销或路由失效无法打开时，移除无效标签并回到工作台。

## 4. 路由记录模型

每条记录包含：

```ts
interface RouteHistoryEntry {
  key: string
  href: string
  title: string
  pattern: string
  visitedAt: number
  pinned: boolean
}
```

字段含义：

- `key`：用于去重的稳定键。
- `href`：最后一次访问的 `pathname + search + hash`，点击标签时使用。
- `title`：用户可读标签标题。
- `pattern`：匹配到的路由定义路径，用于迁移和失效判断。
- `visitedAt`：最近激活时间，用于溢出区域优先级。
- `pinned`：当前仅工作台为 `true`。

### 4.1 路由键规则

- 普通模块使用规范化 pathname，例如 `/employees`。
- 查询参数和 hash 不参与 `key`，只更新同一记录的 `href`。
- 动态对象详情保留对象标识，例如 `/spaces/projects/project-123` 与 `/spaces/projects/project-456` 是两个标签。
- 项目详情的内部 section 不生成新标签，统一归入对应项目键。
- 员工详情按 employeeId 区分。
- 旧重定向路由不进入历史；只记录重定向后的规范地址。

### 4.2 标题规则

- 普通模块使用 `RouteDefinition.title`。
- 项目详情优先显示项目名称，未加载时显示“项目详情”。
- 员工详情优先显示员工姓名，未加载时显示“员工进展”。
- 动态名称加载完成后原位更新标题，不新增记录、不改变顺序。
- 标题长度由视图截断，持久化保存完整文本。

## 5. 状态与持久化

### 5.1 状态边界

历史路由由独立 hook 或 store 管理，`WorkspaceHeader` 只负责渲染和触发操作。状态层提供：

- `visit(location, route, titleOverride?)`
- `activate(key)`
- `close(key)`
- `closeOthers(key)`
- `updateTitle(key, title)`
- `restore(userId)`

### 5.2 用户隔离

存储键包含当前登录用户稳定 ID：

```text
rd-workbench:route-history:v1:<userId>
```

未登录状态不读取或写入受保护页面历史。用户切换后立即加载对应记录，不沿用前一账号的内存状态。

### 5.3 数据保护

- 解析失败、字段类型错误或版本不匹配时丢弃损坏数据，只恢复固定工作台。
- 最多保存 20 个非固定标签；超过后淘汰最久未访问且非当前的标签。
- 不持久化访问令牌、页面正文、表单数据或敏感查询内容。
- 持久化 `href` 前移除参数名为 `token`、`access_token`、`refresh_token`、`password`、`secret`、`code` 的查询参数（大小写不敏感）；普通筛选与内部页签参数保留，以便恢复最后工作位置。

## 6. 自适应与视觉规则

- 使用现有工作台 token，不新增第二套主题。
- 标签轨道采用 Flex 布局，标签宽度使用 `min()`、`max()` 或 `clamp()`，不依赖固定屏幕宽度。
- 使用 `ResizeObserver` 测量真实可用宽度和标签宽度，计算可见集合。
- 计算时固定保留工作台、当前标签和“+N”按钮空间，再按最近访问优先填充其他标签。
- 1280px 及以上保持全局搜索可用；更窄布局遵循现有 AppShell 响应式策略。
- 动画仅用于当前指示线、标签进入/退出和菜单展开，时长 120–180ms；遵守 `prefers-reduced-motion`。

## 7. 组件边界

建议新增：

- `RouteHistoryTabs.tsx`：标签轨道、溢出菜单和键盘交互。
- `useRouteHistory.ts`：路由同步、去重、关闭和持久化。
- `routeHistory.ts`：纯函数，包括规范化、恢复校验、淘汰和邻近选择。
- `RouteHistoryTabs.less`：当前工作台专属紧凑样式。

`AppShell` 提供轻量 `RouteHistoryTitleContext`，项目详情和员工详情在真实名称加载后只向该上下文发布当前标签标题；上下文不承载业务对象和页面状态。`WorkspaceHeader` 接收当前路由与该动态标题，并组合 `RouteHistoryTabs`。`AppShell` 继续负责路由匹配，不把历史状态混入页面业务组件。

## 8. 可访问性

- 标签轨道使用 `role="tablist"`，标签使用 `role="tab"` 和 `aria-selected`。
- 关闭按钮提供“关闭〈标题〉”可访问名称。
- 支持左右方向键移动焦点、Enter/Space 激活、Delete/Backspace 关闭非固定标签。
- 溢出按钮包含未显示数量，菜单项可完整键盘操作。
- 焦点环使用现有工作台品牌色，不能只依赖颜色表达当前状态。

## 9. 验收标准

1. 访问新页面只增加一个历史标签；同一路径改变查询参数不增加重复标签。
2. 不同项目和不同员工详情分别形成标签。
3. 工作台始终位于第一位且不可关闭。
4. 关闭当前标签后按左邻居、右邻居、工作台顺序跳转。
5. 刷新页面后恢复当前用户历史，切换用户不串数据。
6. 空间不足时当前标签始终可见，其余正确进入“+N”菜单。
7. 1280、1440、1920 三档视口下不挤压搜索区、不造成页面横向滚动。
8. 键盘可以切换、关闭和打开溢出菜单，屏幕阅读器能识别当前标签。
9. 损坏持久化数据不会导致顶栏崩溃。
10. 原有新建、搜索、通知、设置和账号菜单交互保持不变。

## 10. 测试策略

- 纯函数单测：规范化、去重、查询参数更新、动态对象区分、淘汰、关闭邻近选择和损坏数据恢复。
- 组件测试：当前标签、固定标签、关闭按钮、溢出菜单和键盘操作。
- 集成测试：路由变化自动记录，刷新恢复和用户切换隔离。
- Playwright：1280/1440/1920 下访问多个页面，检查当前标签可见、搜索区未被挤压、关闭后导航正确且无横向溢出。
