# P0 交互基础统一设计

## 目标

在不改变现有业务数据模型和功能范围的前提下，将前端交互基础统一为 Semi Design，并建立可复用、可测试、可持续迁移的工作台组件层。

## 已确认范围

1. 业务页面统一使用 Semi Design；原生日期、时间、下拉控件和 Shadcn 业务组件退出生产页面。
2. 建立工作台设计变量，统一颜色、间距、尺寸、圆角、阴影、层级和交互状态。
3. 统一日期、日期时间、下拉、关联选择、弹窗、抽屉和表单反馈。
4. 建立页面骨架、目录工具栏、保存状态、空状态和错误状态组件。
5. 视图、筛选、分页、选中对象和详情状态使用 URL 查询参数表达。
6. 修复重复主内容地标、焦点样式、无差别动画和弹层滚动等可访问性问题。

## 设计原则

- 保留现有后端接口、数据结构和业务流程；P0 只处理交互基础和前端状态表达。
- 优先封装公共组件，再迁移页面，禁止在页面内继续新增原生控件。
- 迁移过程保持兼容：公共组件使用 Semi 的受控值协议，同时为表单提交提供明确字段值。
- URL 是可分享页面状态的来源；临时输入和未保存草稿仍保留在组件状态。
- 保存失败保留用户输入；自动保存显示明确状态；危险操作提供确认或撤销。
- 每项生产行为先增加失败测试，再实现最小变更。

## 非目标

- 不在 P0 重做项目、会议、知识库或多维表格的业务流程。
- 不新增多人协作、权限、云同步或外部服务。
- 不进行数据库迁移。

## 验收标准

- 静态测试确认生产页面不存在原生日期/时间/下拉和 `@/components/ui` 业务依赖。
- 页面壳中始终只有一个 `main` 地标，所有图标按钮可访问。
- 弹窗操作区、表单间距和错误反馈使用同一套样式。
- 文档、多维表格、项目、我的工作、日历和搜索的主要视图状态刷新后可恢复。
- 前端单元测试、类型检查、契约检查、Lint、构建和 Chromium E2E 全部通过。
