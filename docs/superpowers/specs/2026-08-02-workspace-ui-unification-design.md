# 全站工作区 UI 统一设计规格

## 目标

在不修改业务流程、接口契约、权限判断和数据模型的前提下，统一全部工作区页面的页面头部、内容宽度、工具栏、表格、表单、弹窗、空状态和响应式行为，消除标题重复、文字贴边、按钮拉伸、表格只占半屏、表单过窄和弹窗留白失衡等问题。

## 已确认根因

1. `WorkspaceHeader` 已显示当前路由，模块内容区仍重复渲染同名 `h1` 和宣传式副标题。
2. `app-page` 与 `workspace-page` 两套容器规则并存，前者限制 1280px，后者无限宽，页面宽度没有按场景分类。
3. 工具栏、表格和弹窗由页面单独拼装，没有共同的左筛选、右操作、正文和底部操作契约。
4. `FormView` 使用内联样式和原生按钮，绕过了工作区设计变量和 Semi UI 组件规范。
5. `ProjectWorkspacePage.less` 的工作项页签嵌套块缺少结束括号，使后续计划基线样式被错误限定在工作项工具栏内部。
6. 全局卡片 hover 位移和大面积紫蓝渐变被应用到结构性容器，造成业务页面漂浮、发灰和视觉噪声。

## 页面分类

### 模块列表页

包括我的工作、项目、员工、文档与知识库、多维表格、日历、搜索、风险、问题、决策、会议、合作方、非项目研发、行业情报、资源负荷、统计报表、申报认定、数据安全、系统管理。

- 顶部工作区栏承担模块名称。
- 内容区不再重复显示同名大标题和宣传式说明。
- 内容区从页签、筛选工具栏、看板或数据列表直接开始。
- 页面仍保留一个可访问的主标题，由工作区顶部栏提供。

### 实体详情页

包括项目详情、员工详情、会议详情、文档详情、合作方详情等。

- 保留对象名称、状态、负责人和主要操作组成的实体头部。
- 顶部工作区栏只作为模块上下文，不重复承担对象标题。
- 实体头部和内容页签之间保持固定间距，不使用宣传式副标题。

### 数据工作区

包括多维表格、知识库三栏工作区和日历。

- 允许使用全宽布局，但内部侧栏、数据画布和详情面板必须有明确边界。
- 新增记录优先使用右侧抽屉或响应式表单面板，不在超宽画布中央放置细长表单。

## 统一布局契约

- 页面水平间距：宽屏 32px，中屏 24px，小屏 16px。
- 面板头部：`16px 20px`；正文：`20px 24px`；工具栏：`12px 16px`。
- 字段标签到控件：6–8px；字段行间距：16px；弹窗 footer：`16px 24px`。
- 列表页内容全宽；详情页最大宽度 1440px；普通表单最大宽度 800px；复杂表单最大宽度 960px。
- 所有主操作按钮保持内容宽度，不允许被自动网格拉伸成整列。
- 表格列宽是最小宽度；表格宽度不得小于可用容器宽度，只有实际溢出时才横向滚动。
- 行操作默认保留一个高频直接操作，其余放入“更多”菜单；危险操作与普通操作分组。
- 结构性卡片不做 hover 位移；仅可点击卡片允许轻微状态反馈。

## 视觉方向

采用克制的飞书式浅色生产力界面：中性浅灰画布、纯白内容面板、低对比边界、清晰信息密度。Aurora 渐变仅保留在登录、NOVA 和品牌展示场景，不再覆盖所有业务页面。

## 验收标准

1. 每个模块页只出现一个可见模块标题，不再重复渲染宣传式说明。
2. 1280、1440、1920、2048 宽度下，内容不贴边、不产生无意义整屏留白。
3. 表格填满内容区，分页和操作列稳定，不出现多余横向区域。
4. 表单控件使用 Semi UI 或现有工作区封装，新增记录提交操作始终可见。
5. 弹窗 header、body、footer 间距一致，按钮与边框至少保持 16px 安全距离。
6. 项目计划基线样式在概览页正常生效，桌面横排、中屏两列、小屏单列。
7. 键盘焦点、可访问名称、长文本截断和减少动态效果设置保持有效。
8. 前端定向测试、类型检查、Lint、生产构建和关键页面浏览器回归通过。
