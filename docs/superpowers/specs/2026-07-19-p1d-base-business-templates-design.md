# P1-01D 多维表格业务模板设计

**状态：** 待书面规格确认  
**范围：** 合作方台账、研发申报、风险台账、面试候选跟踪、非项目研发记录  
**前置版本：** P0-D 多维表格最小可用版、P1-01A/B

## 1. 目标

提供五套适合本地研发管理的飞书式多维表格模板。用户从模板中心一键创建真实自定义表、字段和视图，随后可以像普通自定义表一样修改。模板不生成示例记录，不创建占位业务数据，也不改变五张系统预置表。

## 2. 模板模型

模板是后端版本化代码目录，不新增可编辑模板数据库表：

```ts
interface DataTableTemplateDefinition {
  key: string
  version: 1
  name: string
  description: string
  icon: string
  category: 'PARTNER' | 'APPLICATION' | 'GOVERNANCE' | 'INTERVIEW' | 'RESEARCH'
  fields: TemplateFieldDefinition[]
  views: TemplateViewDefinition[]
}
```

- 模板 key 和版本稳定，前后端通过 API 读取目录，不在前端复制字段定义。
- 实例化后的表 `source=CUSTOM`、`presetKey=null`，与模板没有运行时同步关系；后续模板升级不会静默改变已有表。
- 重复使用同一模板被允许；未填写表名时依次生成“模板名”“模板名 2”“模板名 3”。
- 创建过程使用 workspace 级 advisory lock 和单个数据库事务，字段或视图任一失败则整张表不创建。
- 模板中的系统关系目标通过稳定 `presetKey` 解析实际 `targetTableId`，不在定义中硬编码数据库 ID。

## 3. 模板目录

### 3.1 合作方台账

字段：合作方名称（主字段）、类型、合作状态、联系人、手机号、邮箱、关联项目、协议到期日、下次沟通日、合作内容、备注、创建时间。

视图：全部合作方表格、按合作状态看板、协议到期日历、下次沟通日历。

### 3.2 研发申报

字段：申报事项（主字段）、申报类型、阶段、状态、负责人、关联项目、计划开始、计划提交、材料清单、补正内容、提交记录、备注、更新时间。

视图：申报总表、按阶段看板、提交日历、申报甘特。

### 3.3 风险台账

字段：风险标题（主字段）、对象类型、风险等级、状态、负责人、关联项目、发生概率、影响程度、发现日期、计划关闭日、应对措施、关闭日期、备注。

视图：风险总表、按等级看板、按状态看板、计划关闭日历。

### 3.4 面试候选跟踪

字段：候选人（主字段）、岗位、面试阶段、候选状态、评分、面试官、面试时间、面试结论、简历链接、头像/资料附件、备注、更新时间。

视图：候选人总表、按阶段看板、面试日历、候选人画册。

### 3.5 非项目研发记录

字段：事项名称（主字段）、类别、状态、优先级、负责人、开始日期、结束日期、完成百分比、成果链接、复盘记录、备注、更新时间。

视图：研发事项总表、按状态看板、计划甘特、结束日历。

## 4. 字段与视图约束

- 所有模板字段 key 使用小写 snake_case，创建后遵守 P1-01A 的不可修改规则。
- 单选、多选选项由模板显式定义 label、value 和颜色；不得依赖前端默认选项。
- 主字段必须是必填 `TEXT`，每张表只有一个主字段。
- 关联项目字段指向系统“项目总表”，采用单值单向 `RELATION`。
- 模板允许使用 GANTT/GALLERY，但不预置依赖具体业务记录才能成立的 LOOKUP、ROLLUP 或 FORMULA。
- 所有视图都保存明确配置；甘特必须指定开始/结束字段，画册必须指定标题和候选封面字段。

## 5. API

- `GET /api/base/templates`：返回五套模板的 key、版本、名称、描述、图标、类别、字段摘要和视图摘要。
- `GET /api/base/templates/:key`：返回完整模板预览定义。
- `POST /api/base/workspaces/:workspaceId/templates/:key/instantiate`：接收可选 `{ name?: string }`，事务创建并返回含字段/视图的 `DataTable`。

不存在的 workspace/template 返回 404；名称超限或模板定义校验失败返回 400；并发命名冲突在锁内重新计算名称，不覆盖已有表。

## 6. 前端交互

- 左侧“新建数据表”打开模板中心，顶部提供“空白表格”和“从模板创建”。
- 模板以飞书式紧凑卡片展示名称、用途、字段数、视图类型和主要字段摘要。
- 点击模板先进入预览，展示字段和视图清单；用户可修改新表名称，但本批次不在实例化前编辑字段定义。
- 提交期间禁用重复操作；成功后关闭弹窗、刷新 workspace、选中新表并进入默认表格视图。
- 失败保留模板选择和用户输入名称，不出现假成功表。
- 模板创建后，字段管理、视图管理、导入导出和删除行为与普通自定义表完全一致。

## 7. 模板质量门禁

应用启动不自动实例化业务模板。后端加载目录时执行以下校验：

- key、字段 key、视图名称在单个模板内唯一。
- 恰好一个主字段，且主字段必填。
- 视图引用的字段存在且类型兼容。
- 单选/多选存在非空且 value 唯一的选项。
- 关系目标 preset key 存在。
- 所有模板定义深冻结，运行时请求不能修改全局目录。

任一内置模板定义非法时，模板目录接口返回明确错误并记录服务日志，但不影响普通表格读取。

## 8. 测试与验收

### 后端

- 五套目录定义通过质量门禁，非法定义分别覆盖唯一性、主字段、视图引用和选项错误。
- 实例化字段/视图完整、关系目标解析正确、无记录生成。
- 重复实例化自动命名、显式名称保留、事务失败无残留表。

### 前端

- 空白/模板切换、目录卡片、预览、名称编辑、pending 防重复和失败保留状态。
- 创建成功自动选择新表，后续字段和视图管理可用。

### 真实服务验收

1. 逐一创建五套模板并核对字段和默认视图。
2. 确认每张新表记录数都是 0，不存在示例或占位数据。
3. 重复创建同一模板，确认自动编号且原表不被覆盖。
4. 在模板表中新增记录、修改字段、切换甘特/画册并完成导入导出。
5. 清理验收模板表，确认五张系统预置表未被修改。
