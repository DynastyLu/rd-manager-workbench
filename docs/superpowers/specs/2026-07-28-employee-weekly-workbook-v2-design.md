# 员工周报模板 V2 兼容设计

日期：2026-07-28  
状态：用户已确认模板替换与字段完整接入方向，完整功能清单待用户审阅

## 1. 背景

现有员工工作进展模块使用 V1 平铺模板：

- 工作簿固定包含“说明”“工作明细”两个工作表。
- 一项工作占一行。
- 每行重复填写员工姓名。
- 项目、任务、工时、风险与下期计划都存放在同一行。

新的正式周报模板采用完全不同的业务结构：

- 一个“填写说明”工作表。
- 每名员工一个独立工作表。
- 员工工作表上半部分记录本周工作执行情况。
- 员工工作表下半部分记录下一周的结构化工作计划。
- 工作表同时携带员工姓名、部门、工作方向和周期。

这份新模板是后续必须长期使用的正式模板，不是临时导入样例。本设计将它定义为“员工周报模板 V2”，并保留 V1 导入兼容，避免历史文件失效。

本规格增补并覆盖
`docs/superpowers/specs/2026-07-23-employee-work-progress-design.md`
中的 Excel 模板、导入来源定位和下周计划数据结构；原有员工档案、版本替换、审计、周/月快照和项目联动总体原则保持不变。

## 2. 目标与非目标

### 2.1 目标

- 系统直接接受正式 V2 周报文件，不要求人工转换格式。
- 一次上传可解析全部员工工作表。
- 本周工作进入周执行事实，下周工作进入下一周计划事项。
- 保留原工作表、区域和行号，保证错误定位和数据追溯。
- 上传预览阶段完成员工、项目和任务关联。
- 周/月看板继续正确计算，不把下周计划计入本周完成率。
- 系统当前默认模板直接替换为 V2，并根据系统内在职员工动态生成。
- 新模板中的全部业务字段在系统中有对应字段、页面展示、筛选或统计用途，不做一次性丢弃式转换。
- V1 文件继续可上传、预检、提交、恢复和审计。

### 2.2 非目标

- 不引入员工账号、员工自行登录、在线协同填写和审批流。
- 不依赖 Excel 自动汇总结果作为系统指标。
- 不使用大模型自动决定项目、任务或风险关联。
- 不强制在正式模板中增加项目编号、任务编号和工时列。
- 不迁移或重写历史 V1 工作项。

## 3. 已确认的产品决策

1. 系统当前模板直接替换为 V2 多员工分表结构。
2. 页面只提供 V2 正式模板下载；V1 不再展示下载入口，但后台继续兼容旧文件上传。
3. 下半部分“下周工作计划”导入后生成下一自然周的结构化计划事项。
4. 本周执行事项与下一周计划分开存储、分开统计。
5. 新模板没有项目编号和任务编号，项目/任务以及系统要求的工作类型在一次“补充关联”弹窗中集中补充。
6. 新模板没有计划工时和实际工时，工时作为系统内选填补充项；缺失时不按 0 计算。
7. “本周成果 / 问题”默认作为完成情况；状态为“有风险”或“已阻塞”时，同时形成风险候选。
8. Excel 自动汇总仅服务于填写体验，系统提交后从数据库重新计算指标。
9. 模板里的工作方向、计划完成日期、优先级、协作资源和计划说明必须进入正式数据模型，并用于系统功能。

## 4. V2 工作簿协议

### 4.1 工作表组成

工作簿至少包含：

1. 第一张工作表：“填写说明”。
2. 一张或多张员工工作表。

系统不依赖员工工作表的绝对顺序。员工工作表名称应与表内员工姓名一致；不一致时产生阻断错误，防止把一名员工的数据导给另一名员工。

隐藏的系统辅助工作表允许存在，但必须使用约定前缀 `_rdmw_`，且不参与员工数据解析。其他未知可见工作表产生阻断错误。

### 4.2 填写说明工作表

“填写说明”包含：

- 标题与填写说明。
- 员工姓名。
- 部门。
- 工作方向。

该工作表用于整体核对，不作为员工身份的唯一来源。员工身份以员工工作表中的“员工姓名”为主，并与说明表和工作表名称三方校验。

### 4.3 员工工作表元信息

固定读取：

- 员工姓名。
- 部门。
- 工作方向。
- 本周起始日期。
- 本周结束日期。

校验规则：

- 周期开始必须为周一。
- 周期结束必须为对应周日。
- 所有员工工作表必须属于同一周。
- 下周起始和结束日期由系统根据本周周期推导；Excel 显示值只用于交叉校验。
- 部门或工作方向与员工档案不一致时产生非阻断警告，不静默覆盖档案。

### 4.4 本周工作区域

字段顺序：

| 字段 | 必填 | 系统含义 |
| --- | --- | --- |
| 序号 | 否 | 填写辅助，不作为数据库主键 |
| 本周工作内容 | 是 | 工作事项标题 |
| 具体任务 / 预期交付 | 否 | 本期计划与交付说明 |
| 计划完成日期 | 否 | 工作事项计划完成日期 |
| 状态 | 是 | 未开始、进行中、已完成、有风险、已阻塞 |
| 完成进度 | 否 | 0–100 的整数或百分比 |
| 本周成果 / 问题 | 否 | 本期完成情况；风险状态时同时作为风险候选 |
| 下周计划 | 否 | 与当前事项直接相关的后续动作 |

空行判断只看业务内容，不把模板默认值当作有效数据。只有序号、“未开始”和 `0%`，但工作内容、交付、日期、成果和计划均为空时，该行必须被忽略。

### 4.5 下周工作计划区域

字段顺序：

| 字段 | 必填 | 系统含义 |
| --- | --- | --- |
| 序号 | 否 | 填写辅助 |
| 下周重点工作 | 是 | 下一周计划标题 |
| 具体任务 / 预期交付 | 否 | 交付目标 |
| 计划完成日期 | 否 | 下一周计划完成日期 |
| 优先级 | 否 | 低、中、高、紧急；空值为未指定 |
| 所需协作 / 资源 | 否 | 需要的人员、设备、预算或外部支持 |
| 计划说明 | 否 | 执行说明 |
| 备注 | 否 | 其他补充信息 |

下一周计划的周期由本周结束日期向后推导，不信任用户手工输入的跨周日期标题。

### 4.6 公式与安全

- 允许模板在元信息日期和自动汇总单元格中使用约定公式。
- 系统只读取公式缓存结果，不执行 Excel 公式。
- 本周工作和下周计划的可填写区域禁止公式、外部引用、共享公式和易失函数。
- 自动汇总行不导入数据库。
- 文件继续执行 ZIP 结构、大小、解压体积、单元格长度和行数上限检查。

### 4.7 模板字段完整接入矩阵

模板中的字段按以下规则进入系统，不因现有模型暂时没有字段而丢弃：

| 模板字段 | 系统处理 | 功能用途 |
| --- | --- | --- |
| 员工姓名 | 复用员工姓名 | 员工匹配、员工详情、团队筛选 |
| 部门 | 复用员工部门 | 档案差异核对、部门筛选和汇总 |
| 工作方向 | 新增员工工作方向 | 档案展示、筛选、分布看板 |
| 本周起始/结束日期 | 复用导入批次周期 | 周/月归属、版本替换 |
| 序号 | 只保存原始来源 | 错误定位，不作为业务主键 |
| 本周工作内容 | 复用工作标题 | 明细、搜索、项目贡献 |
| 具体任务 / 预期交付 | 作为独立可见交付说明 | 工作详情、搜索、看板摘要 |
| 计划完成日期 | 新增计划完成日期 | 逾期判断、筛选、提醒候选 |
| 状态 | 复用工作状态 | 完成率、风险和阻塞统计 |
| 完成进度 | 复用完成度 | 平均进度和个人/团队趋势 |
| 本周成果 / 问题 | 复用完成情况并生成风险候选 | 成果展示、问题识别、转项目风险 |
| 下周计划 | 复用当前事项后续动作 | 当前工作上下文和后续动作 |
| 下周起始/结束日期 | 系统推导下一周周期 | 下周计划归属 |
| 下周重点工作 | 新增结构化周计划事项 | 下周计划列表和承接跟踪 |
| 下周具体任务 / 预期交付 | 新增计划交付说明 | 计划详情、搜索、项目计划 |
| 下周计划完成日期 | 新增计划完成日期 | 到期筛选、提醒候选 |
| 优先级 | 新增计划优先级 | 排序、高优先级看板 |
| 所需协作 / 资源 | 新增协作资源说明 | 协作需求看板、项目详情 |
| 计划说明 | 新增计划说明 | 执行说明和全文搜索 |
| 备注 | 复用备注 | 详情补充 |
| 自动汇总 | 不保存 Excel 结果 | 系统从正式数据重新计算 |
| 填写提示 | 不入库 | 仅属于模板使用说明 |

“进入系统”至少意味着：正式保存、详情页可见、导入预览可核对、导出可还原；适合筛选、搜索、看板或提醒的字段还必须接入对应功能。

## 5. 模板识别与兼容

上传后先执行格式探测：

### 5.1 V1

满足以下条件时进入现有 V1 解析器：

- 正好包含“说明”“工作明细”。
- 说明表模板版本为 1。
- 工作明细包含现有 13 列。

### 5.2 V2

满足以下条件时进入 V2 解析器：

- 存在“填写说明”。
- 至少一张员工工作表。
- 员工工作表包含 V2 元信息、本周工作表头和下周计划表头。

### 5.3 未识别格式

不进行猜测性列映射。返回“无法识别周报模板”，并展示：

- 已发现工作表。
- 缺少的结构。
- 支持的模板版本。
- 下载正式 V2 模板入口。

## 6. 数据映射

### 6.1 员工档案

继续复用 `ResourceProfile`，增加：

- `workDirection String?`

员工匹配仍以标准姓名精确匹配。预览阶段：

- 已匹配员工：展示档案与 Excel 部门、工作方向差异。
- 未匹配员工：阻断提交，提供“关联现有员工”或“创建员工档案”。
- 档案更新必须由管理员显式勾选确认，默认不覆盖。

### 6.2 本周工作

本周工作继续写入 `EmployeeWorkItem`，新增：

- `plannedCompletionAt DateTime? @db.Date`
- `workKind`：`PROJECT`、`NON_PROJECT`

映射：

- 本周工作内容 → `title`
- 具体任务 / 预期交付 → `planText`，系统页面统一显示为“具体任务 / 预期交付”
- 计划完成日期 → `plannedCompletionAt`
- 状态 → `status`
- 完成进度 → `completionRate`
- 本周成果 / 问题 → `summaryText`
- 下周计划 → `nextPlanText`

当状态为 `AT_RISK` 或 `BLOCKED` 且“本周成果 / 问题”非空时：

- 预览中标记为风险候选。
- 默认将同一文本写入 `riskText`。
- 管理员可以在预览中取消风险候选或修改风险说明。

### 6.3 下一周计划

新增 `EmployeeWeekPlanItem`：

- `id`
- `employeeId`
- `importBatchId`
- `sourceRowId`
- `periodStartAt`
- `periodEndAt`
- `title`
- `deliverableText`
- `plannedCompletionAt`
- `priority`：`LOW`、`MEDIUM`、`HIGH`、`URGENT`、`UNSPECIFIED`
- `collaborationText`
- `planText`
- `note`
- `workKind`：`PROJECT`、`NON_PROJECT`
- `projectId`
- `taskId`
- `carryStatus`：`PLANNED`、`MATCHED`、`CANCELLED`
- `matchedWorkItemId`
- `rawRow`
- `archivedAt`
- `createdAt`
- `updatedAt`

下一周计划不参与本周完成率、平均进度、完成事项和风险数量计算。

下一周正式周报导入时，系统用“员工 + 规范化标题”进行精确承接建议：

- 只产生建议，不静默合并。
- 管理员确认后，将计划标记为 `MATCHED` 并关联实际工作项。
- 未被承接的计划继续显示为“未承接计划”，用于主管追踪。

### 6.4 导入来源定位

扩展 `EmployeeWorkImportRow`：

- `sourceSheetName`
- `sourceSection`：`CURRENT_WORK`、`NEXT_WEEK_PLAN`
- `sourceRowNumber`
- `sourceKey`

`rowNumber` 保留为批次内全局顺序，兼容现有分页和接口。真实来源定位使用：

```text
员工工作表 / 本周工作 / 第 7 行
```

`sourceKey` 在批次内唯一，组成方式为：

```text
<工作表名称>:<区域>:<原始行号>
```

## 7. 项目、任务与工时补充

V2 模板没有项目、任务和工时字段，因此预览向导增加补充步骤。

每条本周工作和下一周计划均支持：

- 必须明确选择“项目工作”或“非项目工作”。
- 选择关联项目。
- 选择项目下的任务。
- 非项目工作保持项目和任务为空。
- 对当前员工、当前工作方向或选中行批量关联项目。
- 根据标题和交付描述展示候选项目/任务。

候选只用于排序，不自动确认。最终关联必须由管理员选择。

必填规则：

- 未识别员工必须关联现有员工或创建员工档案。
- `workKind = PROJECT` 时项目必填、任务选填。
- `workKind = NON_PROJECT` 时项目和任务必须为空。
- 项目工作不能以“保持未关联”绕过确认；尚未确定项目时应改为非项目工作，后续可在系统中调整并留下审计记录。
- 计划工时和实际工时始终选填。

补充关联采用一个表格式弹窗，不为每一行连续打开独立弹窗。弹窗列包括：

- 员工
- 工作表与原始行号
- 本周工作/下周计划
- 工作标题
- 工作类型
- 关联项目
- 关联任务
- 计划工时
- 实际工时（仅本周执行）
- 风险候选
- 校验状态

支持多选后批量设置工作类型、项目和任务，并对缺少必填关联的单元格高亮。

工时处理：

- V2 导入默认 `plannedHours = null`、`actualHours = null`。
- 预览和导入后详情页允许选填计划/实际工时。
- 资源负荷和工时指标缺少数据时显示“工时未填”或“数据不完整”。
- 不把缺失工时当作 `0`，不生成虚假的空闲结论。

## 8. 导入流程

为了降低管理员操作量，V2 不使用多个分散页面，而采用“上传 + 单个补充关联弹窗 + 确认”的流程：

1. **上传正式周报**：系统自动识别 V2、周期和员工工作表。
2. **自动预检**：后台一次完成结构、员工、日期、状态、进度、字段和公式校验。
3. **补充关联弹窗**：集中处理未知员工、档案差异、工作类型、项目、任务、风险候选和可选工时。
4. **确认导入**：展示版本替换、本周事项数、下周计划数、项目工作数、非项目工作数和影响范围。

如果文件没有需要人工补充的内容，仍展示汇总确认页，但不强制进入空的补充表格。

提交仍保持原子性：

- 本周工作和下周计划必须在同一事务中写入。
- 任何正式写入失败，整个批次回滚。
- 原文件、暂存行和错误信息保留，便于修正和重试。
- 同周期重新上传继续采用版本替换；旧版本的工作和计划同时归档。

## 9. 页面与看板影响

### 9.1 员工详情

工作进展区域分为：

1. **本周执行**
   - 工作事项
   - 具体任务 / 预期交付
   - 工作类型
   - 项目/任务
   - 计划完成日期
   - 状态
   - 完成进度
   - 成果/问题
   - 风险

2. **下周计划**
   - 重点工作
   - 具体任务 / 预期交付
   - 工作类型
   - 项目/任务
   - 优先级
   - 交付目标
   - 计划完成日期
   - 所需协作/资源
   - 计划说明
   - 备注
   - 承接状态

员工档案页增加“工作方向”，员工工作详情和列表支持按工作方向、计划完成日期和工作类型筛选。

### 9.2 团队总览

继续展示：

- 本周工作数
- 已完成数
- 完成率
- 平均进度
- 风险数
- 阻塞数
- 项目关联率

新增：

- 工作方向分布
- 计划完成日期已逾期事项
- 下一周重点计划数
- 高/紧急优先级计划
- 需要协作资源的计划数
- 未承接计划

### 9.3 月度看板

- 本周执行事项参与周/月完成指标。
- 下一周计划不作为已执行事实参与完成指标。
- 计划可用于“计划 vs 实际承接”统计。
- 缺少工时的周期明确标记数据不完整。

### 9.4 项目详情

项目“进展”页继续展示员工当前周贡献，并增加：

- 与项目关联的下周计划。
- 所需协作/资源。
- 未承接计划。
- 计划完成日期和优先级。

### 9.5 搜索与提醒

- 全局搜索索引本周工作标题、预期交付、成果/问题、下周计划标题、计划说明和协作资源。
- 搜索结果区分“本周执行”和“下周计划”，并可跳转到对应员工或项目。
- 计划完成日期进入现有提醒体系的候选来源。
- 系统默认不因导入自动发送短信；管理员可以在系统中为到期事项启用页面通知、桌面通知或已配置的短信渠道。
- 逾期判断使用本地日期，不因时区换算把日期提前或延后一天。

## 10. 正式模板下载

默认“下载导入模板”改为动态生成 V2：

- 管理员选择周一日期。
- 系统读取全部在职员工。
- 为每名员工生成独立工作表。
- 自动填入姓名、部门、工作方向、本周和下周日期。
- 保留正式模板的视觉样式、黄色填写区、数据验证和自动汇总公式。

页面不再提供 V1 模板下载入口。V1 生成能力和上传解析器暂时保留，仅用于历史兼容和自动化回归。

不得把用户提供的包含真实员工姓名的原始文件提交为测试夹具或项目资产。自动化测试应生成匿名、结构等价的 V2 工作簿。

## 11. API 影响

保持现有上传入口，服务端自动探测版本：

```text
POST /api/employee-work-imports
```

模板下载支持：

```text
GET /api/employee-work-imports/template?version=2&periodStart=YYYY-MM-DD
```

V1 模板生成接口不在前端暴露；现有 V1 文件仍可通过统一上传入口导入。

导入详情响应增加：

- `templateVersion`
- `employeeSheetCount`
- `currentWorkRowCount`
- `nextWeekPlanRowCount`
- `profileWarnings`
- `sourceSheetName`
- `sourceSection`
- `sourceRowNumber`

员工和团队进展接口增加下一周计划集合与统计，但保持现有本周指标字段含义不变。

## 12. 错误处理

### 12.1 阻断错误

- 模板无法识别。
- 未知可见工作表。
- 员工工作表名称、说明表姓名、表内姓名不一致。
- 员工工作表周期不一致。
- 周期不是周一至周日。
- 本周或下周表头被删除、改名或移动。
- 必填工作标题缺失但存在其他业务内容。
- 状态、进度、优先级或日期值无效。
- 可填写区域存在公式或外部引用。
- 未知员工尚未映射或创建。
- 任务不属于所选项目。

### 12.2 非阻断警告

- 部门与员工档案不一致。
- 工作方向与员工档案不一致。
- 项目工作未选择具体任务。
- 工时未填写。
- 风险候选尚未确认。
- 下周计划日期超出下一自然周。

所有错误必须显示员工工作表、区域、原始行号、字段和可执行的修正建议，不向用户展示 Prisma 或 ExcelJS 内部错误。

## 13. 迁移与兼容

- 只增加可空字段、新枚举和新表，不修改历史 V1 数据。
- 现有 `EmployeeWorkItem` 的 `plannedCompletionAt` 默认为空。
- 现有导入行的来源工作表和区域为空，页面继续显示旧的“第 N 行”。
- V1 导入、预览、错误文件、提交、版本替换和恢复测试必须继续通过。
- V2 与 V1 使用相同的批次状态机、预览指纹、审计和快照框架。
- 备份恢复自动包含新增表和字段。

## 15. 验收标准

- 用户提供的正式 V2 周报可以直接上传并完成预检。
- 所有有效员工工作表均被解析，空模板行不会产生工作事项。
- 本周工作与下周计划分别落库、分别展示、分别统计。
- 下一周计划直接生成下一自然周计划事项。
- 每条工作均明确分类为项目工作或非项目工作；项目工作必须关联项目，任务选填。
- 部门和工作方向差异不会静默覆盖员工档案。
- Excel 自动汇总与数据库指标不一致时，以数据库为准。
- V1 历史文件和现有历史数据继续可用。
- 缺失工时不会被错误计算为零。
- 模板中除序号、填写提示和自动汇总外的全部业务字段均进入正式系统功能。
- 所有错误均定位到工作表、区域、行号和字段。
- 不提交包含真实员工信息的源周报文件。

## 16. 完整功能清单

以下清单是本功能开发与验收的完整范围。除明确标记为兼容或派生的数据外，新模板中的业务信息不得在任一环节丢失。

### 16.1 正式模板管理

- **WT-001**：系统默认“下载周报模板”直接生成 V2，不再向普通用户展示 V1 模板。
- **WT-002**：下载前选择本周周一，系统自动计算本周周日和下一周起止日期。
- **WT-003**：模板读取所有在职员工，一名员工生成一张独立工作表。
- **WT-004**：模板自动填写员工姓名、部门和工作方向。
- **WT-005**：模板包含“填写说明”员工目录、本周工作区域、自动汇总区域和下周计划区域。
- **WT-006**：状态、完成进度和优先级使用 Excel 下拉验证。
- **WT-007**：日期单元格使用真实 Excel 日期格式，不使用不可排序的日期文本。
- **WT-008**：可填写区域保持正式模板的黄色底色、列宽、行高、冻结、边框和换行。
- **WT-009**：自动汇总公式只服务 Excel 填写，不作为系统导入后的权威指标。
- **WT-010**：员工数量变化时，新下载模板按当前在职档案生成，不复用旧员工名单。
- **WT-011**：V1 模板生成能力仅保留给兼容测试和历史支持。

### 16.2 文件上传与格式识别

- **WI-001**：只接受 `.xlsx`，校验扩展名、MIME、文件大小和 ZIP 结构。
- **WI-002**：计算文件哈希，避免同一文件在未过期批次中被重复上传。
- **WI-003**：自动识别 V1 平铺模板和 V2 员工分表模板。
- **WI-004**：V2 必须存在“填写说明”和至少一张有效员工工作表。
- **WI-005**：员工工作表顺序不影响解析。
- **WI-006**：仅允许约定的隐藏辅助工作表，未知可见工作表阻断导入。
- **WI-007**：展示识别出的模板版本、周期、员工工作表数量、文件名和上传时间。
- **WI-008**：无法识别时展示缺失结构和正式模板下载入口，不显示内部解析异常。

### 16.3 员工与周期校验

- **EV-001**：员工工作表名称、说明表员工姓名和工作表内员工姓名三方一致。
- **EV-002**：员工按标准姓名精确匹配系统员工档案。
- **EV-003**：未知员工必须在补充弹窗中关联现有员工或创建员工档案。
- **EV-004**：已离职或已归档员工产生阻断提示，不能静默写入。
- **EV-005**：部门差异作为警告展示。
- **EV-006**：工作方向差异作为警告展示。
- **EV-007**：管理员可显式选择是否用 Excel 数据更新部门和工作方向，默认不更新。
- **EV-008**：所有员工工作表必须属于同一自然周。
- **EV-009**：本周开始必须为周一，结束必须为对应周日。
- **EV-010**：下一周周期由系统推导，并与模板显示值交叉校验。
- **EV-011**：日期解析不受 Windows/macOS 时区差异影响。

### 16.4 本周工作解析

- **CW-001**：读取本周工作内容。
- **CW-002**：读取具体任务/预期交付。
- **CW-003**：读取计划完成日期。
- **CW-004**：读取状态并映射未开始、进行中、已完成、有风险、已阻塞。
- **CW-005**：读取整数或百分比形式的完成进度。
- **CW-006**：读取本周成果/问题。
- **CW-007**：读取与当前事项直接相关的下周计划。
- **CW-008**：序号、默认未开始和默认 0% 不足以构成有效工作行。
- **CW-009**：业务字段全部为空的模板占位行必须忽略。
- **CW-010**：业务字段部分填写但缺少工作标题时产生阻断错误。
- **CW-011**：计划完成日期超期后计算逾期状态，但不自动修改员工填写的工作状态。
- **CW-012**：导入后保留原始工作表、区域、行号和原始单元格值。

### 16.5 下周计划解析

- **NW-001**：读取下周重点工作。
- **NW-002**：读取具体任务/预期交付。
- **NW-003**：读取计划完成日期。
- **NW-004**：读取优先级。
- **NW-005**：读取所需协作/资源。
- **NW-006**：读取计划说明。
- **NW-007**：读取备注。
- **NW-008**：空模板行忽略，部分填写但缺少重点工作标题时阻断。
- **NW-009**：每条有效记录生成下一自然周的独立计划事项。
- **NW-010**：下周计划不计入本周完成率、平均进度和已完成事项。
- **NW-011**：下周计划日期超出下一自然周时给出警告，允许管理员确认保留。
- **NW-012**：保留原始工作表、区域、行号和原始单元格值。

### 16.6 补充关联弹窗

- **AR-001**：上传预检后使用一个表格式弹窗集中补充，不逐行连续弹出小弹窗。
- **AR-002**：弹窗按员工分组，并支持搜索员工、工作标题和来源行。
- **AR-003**：支持切换“全部、本周工作、下周计划、待处理、错误”。
- **AR-004**：展示员工、来源工作表、原始行号、工作标题、交付说明和校验状态。
- **AR-005**：每条记录必须选择项目工作或非项目工作。
- **AR-006**：项目工作必须选择项目。
- **AR-007**：选择项目后任务选项只展示该项目内任务。
- **AR-008**：任务选填，未选任务不阻断项目工作导入。
- **AR-009**：非项目工作自动清空项目和任务。
- **AR-010**：支持计划工时选填。
- **AR-011**：本周工作支持实际工时选填；下周计划不显示实际工时。
- **AR-012**：支持确认、取消或修改风险候选。
- **AR-013**：支持多选批量设置工作类型、项目和任务。
- **AR-014**：批量更换项目时自动清除不属于新项目的任务。

- **AR-017**：弹窗关闭后再次打开，已补充内容保持在暂存批次中。
- **AR-018**：未解决阻断错误时确认导入按钮禁用。
- **AR-019**：确认页展示本周事项数、下周计划数、项目工作数、非项目工作数、风险候选数和工时缺失数。

### 16.7 本周执行功能

- **CF-001**：员工详情展示工作标题、交付说明、工作类型、项目、任务、计划完成日期、状态、进度、成果/问题、后续动作、风险、工时和来源。
- **CF-002**：计划完成日期用于即将到期和逾期判断。
- **CF-003**：状态为已完成但进度不足 100%，或进度为 100% 但状态未完成时显示数据一致性提示。
- **CF-004**：项目工作可跳转对应项目和任务。

- **CF-008**：支持从风险候选转为正式项目风险，重复转换保持幂等。

### 16.8 下周计划功能

- **NF-001**：员工详情独立展示下一周计划列表。

- **NF-005**：同一计划重复转换任务保持幂等。

- **NF-007**：承接必须由管理员确认，不静默合并。
- **NF-008**：确认承接后关联实际工作项并标记已承接。
- **NF-009**：未承接、已承接和已取消计划分别展示。
- **NF-010**：取消计划必须记录原因和审计日志，不删除原始来源。

### 16.9 项目与任务联动

- **PT-004**：员工工作可穿透到项目、任务和项目风险。
- **PT-005**：项目可反向穿透到员工详情和原始导入批次。
- **PT-006**：任务必须属于所选项目，前后端同时校验。

### 16.10 风险与问题闭环

### 16.13 搜索、筛选与快捷操作

- **SF-001**：全局搜索覆盖员工、工作方向、本周标题、交付、成果/问题、下周计划、计划说明和协作资源。
- **SF-002**：搜索结果区分本周执行和下周计划。
- **SF-003**：支持按周期、员工、部门、工作方向、工作类型、项目、任务、状态、优先级、日期、风险和承接状态筛选。
- **SF-004**：支持一键打开员工详情、项目详情、任务或来源批次。
- **SF-005**：支持从搜索结果执行补充关联、转风险、转任务等有权限的快捷操作。

### 16.14 提醒与通知

- **NT-001**：本周工作和下周计划的计划完成日期进入提醒候选。
- **NT-002**：导入本身不自动发送短信，避免批量误发。
- **NT-003**：管理员可为事项启用页面通知、Socket 实时通知和 Electron 桌面通知。
- **NT-004**：已配置短信服务商和收件人时，可显式启用短信提醒。
- **NT-005**：提醒默认支持提前一天、到期当天和逾期后，具体时间可配置。
- **NT-006**：事项完成、取消或计划日期变化后同步取消或重排未发送提醒。
- **NT-007**：通知记录保留渠道、时间、结果和失败原因。

### 16.15 版本、恢复与审计

- **VA-001**：同一周期首次提交生成 v1，再次提交生成 v2、v3。
- **VA-002**：新版本提交成功后旧版本标记为已被替换，不物理删除。
- **VA-003**：本周工作、下周计划、负荷记录和快照按同一版本一起切换。
- **VA-004**：版本替换必须事务化，失败时回滚。
- **VA-005**：支持下载原始上传文件和错误行文件。
- **VA-006**：支持基于历史版本创建恢复版本。
- **VA-007**：恢复不覆盖历史记录，而是生成新的当前版本。
- **VA-008**：上传、预检、关联、档案更新、提交、替换、恢复、工时修改、风险转换和计划承接写入审计日志。
- **VA-009**：重复点击提交、转风险、转任务和恢复保持幂等。

### 16.16 导出与数据回读

- **EX-001**：工作明细可按当前筛选导出 Excel/CSV。
- **EX-002**：导出包含模板业务字段、系统补充字段、项目/任务、工时、风险和来源。
- **EX-003**：员工详情支持导出个人周报。
- **EX-004**：团队看板支持导出周/月汇总。
- **EX-005**：下一周期模板生成时可参考上一周未承接计划，但必须由管理员选择是否带入。
- **EX-006**：业务字段导出后再导入不应发生内容丢失或日期错位。

### 16.17 UI 与交互质量

- **UX-001**：所有表单、日期、下拉、弹窗和表格使用现有 Semi Design 组件。
- **UX-002**：补充关联弹窗底部操作区固定并保留统一边距。
- **UX-003**：大批量数据支持固定表头、横向滚动、分页或虚拟滚动。
- **UX-004**：保存、预检和提交过程展示明确进度和当前阶段。
- **UX-005**：错误、警告、成功和处理中状态颜色统一。
- **UX-006**：禁止向页面直接输出 Prisma、ExcelJS、SQL 或堆栈错误。
- **UX-007**：Windows 和 macOS 浏览器/Electron 下布局、日期和文件名显示一致。
- **UX-008**：键盘可访问，表格批量操作、弹窗和错误定位具备可识别标签。

### 16.18 性能、安全与测试

- **QS-001**：解析设置文件大小、工作表数、有效行数、单元格长度和解压体积上限。
- **QS-002**：禁止填写区公式、外部工作簿引用和易失函数。
- **QS-003**：原文件保存在工作台受控目录，不使用用户文件名作为任意磁盘路径。
- **QS-004**：数据库查询、筛选和排序参数化，禁止拼接用户文本 SQL。
- **QS-005**：真实员工周报不进入 Git、测试夹具或日志正文。
- **QS-006**：自动化测试使用匿名生成的 V2 工作簿。
- **QS-007**：V1 回归、V2 单元、集成、前端、端到端、类型检查、Lint 和生产构建全部通过。
- **QS-008**：在 Windows 和 macOS 各执行一次真实模板导入验收。
- **QS-009**：备份恢复包含新增字段、计划事项、关联、负荷、版本和审计数据。
