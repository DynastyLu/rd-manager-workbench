# 本地研发工作台：工作空间导航与应用外壳设计

> 本规格取代 `2026-07-18-feishu-local-experience-design.md` 中的导航分组。原规格中的功能范围仍作为领域清单保留；本规格重新定义这些功能在产品中的入口、层级与呈现方式。

## 目标

把研发主管本地工作台从“多个后台 CRUD 页面”重构为单人、本地优先的研发工作空间。交互组织参考飞书桌面端的稳定导航、对象空间、资料沉淀和快捷切换习惯，但不复制飞书品牌、图标、文案或协作系统。

用户进入系统后应先看到当前该做的工作，随后从项目空间、业务库、会议资料和知识库连续处理研发对象，而不是在风险、会议、合作方等相互割裂的管理页面之间跳转。

## 产品边界

### 本期保留

- 单机、本地 PostgreSQL、单一使用者和 Electron 桌面外壳方向。
- 已有项目、任务、里程碑、进展、申报认定、风险、问题、决策、合作方、会议和行动项的数据与 API。
- 本地附件、提醒、搜索、导入导出、备份恢复、审计、行业情报、非项目研发和报表等既有规划。
- 新增的本地知识库：知识页、目录、标签、模板、关联对象和全文检索。

### 明确不做

- 账号、组织、权限、群聊、消息、@提及、协同编辑、评论线程和在线状态。
- 云同步、跨设备冲突处理、飞书开放平台、飞书云文档/网盘/日历双向同步。
- 为填满页面而创建的假业务数据。未完成模块必须显示其真实空状态或“规划中”说明。

## 总体信息架构

顶层导航只按使用场景分组；业务对象不再逐一成为顶层后台菜单。

| 顶层入口 | 责任 | 当前归属的业务能力 |
| --- | --- | --- |
| 工作台 | 打开应用后的行动总览与快捷新建 | 今日任务、近期会议、临期事项、项目健康度、提醒、动态摘要 |
| 我的工作 | 面向个人的执行队列 | 任务、待处理行动项、个人日程、稍后处理与提醒 |
| 项目空间 | 研发项目的连续工作区 | 项目概览、里程碑、任务、进展、风险问题、会议、资料、关联情报 |
| 业务库 | 跨项目查找、筛选和维护研发业务对象 | 申报认定、风险、问题、决策、合作方、行业情报、非项目研发 |
| 会议与资料 | 会议过程与原始资料的沉淀 | 会议、议程、纪要、行动项、附件和材料版本 |
| 知识库 | 可复用的研发认知与经验资产 | 知识页、目录、标签、模板、项目复盘、关联对象、全文搜索 |
| 自动化与数据 | 本机数据维护与规则能力 | 提醒、全局搜索、Excel/CSV 导入导出、备份恢复、审计、采集计划 |
| 设置 | 应用偏好与本机环境 | 数据库连接状态、存储目录、通知和界面偏好 |

## 路由模型

新路由是唯一的可见导航入口；现有 URL 保留为重定向，避免书签和已打开标签失效。

| Canonical route | 页面 | 旧路由的迁移 |
| --- | --- | --- |
| `/` | 工作台 | 保持 |
| `/my-work` | 我的工作 | `/tasks` 重定向到该页的任务视图 |
| `/spaces/projects` | 项目空间列表 | `/projects` 重定向 |
| `/spaces/projects/:projectId/:section?` | 单一项目工作区 | 项目详情的新固定入口 |
| `/library` | 业务库首页 | 新增 |
| `/library/applications` | 申报认定库 | `/application-cases` 重定向 |
| `/library/governance/:kind` | 风险、问题、决策、合作方等对象库 | `/risks`、`/issues`、`/decisions`、`/partners` 重定向 |
| `/meetings` | 会议与资料首页 | 旧会议页迁入 |
| `/knowledge` | 知识库首页 | 新增，先为规划中页面 |
| `/automation-data` | 自动化与数据首页 | 新增 |
| `/settings` | 设置 | 保持 |

`kind` 的首批合法值为 `risks`、`issues`、`decisions`、`partners`、`intelligence`、`operations`。尚无真实 API 的 `intelligence` 和 `operations` 仍可被路由识别，但必须展示规划状态，不发出不存在的请求。

## 应用外壳

### 布局

- 固定、紧凑的左侧主导航：只显示上表八个入口；设置位于底部。
- 顶部工具栏：全局搜索入口、快速新建、当前本地空间状态和主题偏好；不保留传统“页面多标签栏”。
- 主内容区：每页有统一的面包屑、标题、上下文操作和内容区；列表页不再使用后台式的“标题 + 大表格”作为唯一形态。
- 桌面优先但可缩放：窄窗口时导航仅保留图标和悬浮标题；内容区不横向截断关键操作。

### 页面形态

1. **工作台**：行动卡、项目脉冲、近期会议/提醒和快捷新建；每张卡链接到真实对象或真实空状态。
2. **空间列表**：卡片、列表和搜索可切换。项目是首个空间类型，后续可增加申报空间或主题空间，但不提前抽象泛用引擎。
3. **对象工作区**：项目详情的固定二级导航为“概览、任务、进展、风险与问题、会议、资料”。没有可用数据的二级项展示空状态和创建入口。
4. **业务库**：先提供业务库总览，再进入单一对象类型的可筛选列表与详情抽屉/页面；跨项目检索从这里进入。
5. **知识库**：目录树 + 知识页列表 + 当前正文三栏结构。第一期知识页关联项目、会议、情报、任务和附件；正文存储格式、富文本编辑器和全文索引在知识库实施计划中确定。
6. **自动化与数据**：按“行动提醒、查找数据、交换数据、保护数据”分区，而不把运维能力伪装成业务菜单。

## 组件与职责边界

| 单元 | 责任 | 不负责 |
| --- | --- | --- |
| `AppShell` | 主导航、顶栏、页面容器和窄窗口行为 | 业务 API、页面数据加载 |
| route registry | canonical route、标题、导航归属、旧路由重定向 | 组件内的筛选状态 |
| `WorkspaceHeader` | 面包屑、页面标题、上下文操作、二级导航 | 业务详情读取 |
| `ModuleDirectory` | 业务库或自动化与数据的能力目录、状态标签 | 伪造未实现模块数据 |
| `ProjectWorkspace` | 将现有项目、任务和关联对象放进统一的项目上下文 | 通用的任意对象编辑引擎 |
| `PlannedModuleState` | 说明模块尚未落地的范围、下一步与可用替代入口 | 网络请求或虚假统计 |

## 数据流与状态

- 外壳和导航不依赖后端；页面数据仍通过现有 React Query API 层读取。
- 进入对象工作区时只加载当前页签所需数据；切换页签复用缓存，并保持当前项目上下文。
- 工作台只汇总已存在的真实接口。某项接口尚未实现时，该区块显示“规划中”，不返回伪造计数。
- 全局搜索在数据治理完成前显示入口和功能边界，不能向后端发送未实现请求。
- 创建操作统一从快速新建菜单或当前工作区上下文启动；成功后定位真实对象，失败时展示 API 返回的可读错误并保留表单输入。

## 错误、空状态与迁移

- 加载失败必须表明是哪一类本地数据未读到，并提供重试；不能笼统提示“无法读取本地工作台”。
- 空状态必须给出可执行的下一步（新建、导入、前往关联空间）或明确“该能力正在规划”。
- 旧路由使用 `Navigate replace` 跳到 canonical route；不删除旧 path 常量，直到至少一个稳定版本后再评估。
- 原有 API、数据库表和已迁移数据不改名、不删除；本次首先是前端信息架构重构，后续模块通过新入口接入。

## 交付顺序

1. 新 route registry、重定向规则、`AppShell`、统一标题区和导航测试。
2. 工作台、我的工作、项目空间列表及项目工作区骨架；把现有项目/任务真实数据接入。
3. 业务库、会议与资料、申报和管理闭环现有页面迁入新入口。
4. 知识库数据模型/API/UI，随后接入附件、情报、提醒、全局搜索与数据治理。
5. 非项目研发、资源负荷、报表、AI、外部集成和 LAN 等扩展，均作为新架构下的增量实现。

## 验收与测试

- 路由测试验证每个顶层入口、canonical route、legacy redirect 和未知路径兜底。
- 组件测试验证导航当前态、窄窗口行为、规划中模块不会调用 API、加载/空/失败状态与重试。
- 项目工作区测试验证页签切换保留项目上下文，并且真实任务/项目 API 错误能被页面反馈。
- 端到端冒烟验证从工作台进入项目空间、进入项目工作区、返回业务库；已有 `/projects`、`/tasks` 等旧 URL 应落到新页面。
- 知识库实施前补充独立数据模型、对象引用、全文检索与附件访问规则测试；本规格不预设其表结构。
