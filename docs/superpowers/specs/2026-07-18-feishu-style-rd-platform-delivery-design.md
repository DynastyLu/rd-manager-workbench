# 飞书式本地研发工作系统：全功能交付设计

> 本规格以本地单人研发主管为对象，借鉴飞书项目、任务日历、业务对象库、知识库、资料和自动化的组织方式；不复制飞书的品牌、资产、云服务或协同机制。本规格在导航外壳规格之上定义后续前后端功能交付顺序。

## 目标与边界

目标是把研发管理变成连续的本地工作流：从项目目标和行动项开始，经由会议、风险、资料、情报和知识沉淀，最终可检索、可备份、可复盘。

- 所有新数据持久化到本机 PostgreSQL，所有附件存到配置的本机目录。
- 前端通过既有 `/api` 和 TanStack Query 读取；后端以 NestJS 模块、Prisma 迁移和可测试服务实现。
- 第一版只有一个本地使用者：不做账号、组织、权限、聊天、@提及、评论、云同步、在线协作、飞书 OAuth/API。
- 所有列表、计数、日程和搜索结果必须来自本机数据；未实现能力显示规划状态，不生产假数据。

## 飞书式功能映射

| 飞书式体验 | 本地研发实现 |
| --- | --- |
| 飞书项目的项目流程、任务拆分、里程碑、排期与详情关联对象 | 项目空间：概览、任务、进展、风险与问题、会议、资料页签；项目为所有研发对象的主要上下文 |
| 任务与日历 | 我的工作：收件箱、今日/本周、日历视图、提醒、稍后处理；只管理本地行动项 |
| 多维表格/业务对象库 | 业务库：项目、申报、风险、问题、决策、合作方、情报、非项目研发的可筛选对象库和关联详情 |
| 会议纪要、云文档/云空间 | 会议与资料：议程、纪要、行动项、附件、材料版本和对象关联 |
| 知识库的空间、目录、知识页和检索 | 本地知识库：层级目录、知识页、标签、模板、对象反向链接和全文检索 |
| 自动化、搜索、导入导出与管理能力 | 本地提醒、全局搜索、Excel/CSV、备份恢复、审计和情报采集计划 |

飞书项目的公开介绍强调项目流程、进度/里程碑、排期工时、任务拆解与详情关联；飞书知识库强调层级化沉淀与检索。本系统采用这些对象组织原则，但将协作能力替换为本地追溯和个人工作流。[飞书项目介绍](https://www.feishu.cn/content/2jwuo1fq) [飞书知识库](https://www.feishu.cn/product/wiki)

## 统一关联模型

所有后续领域对象均可选关联 `projectId`。可关联对象包括任务、进展、风险、问题、决策、会议、附件、知识页、情报卡和非项目研发记录。

- 项目详情页只读取已有的项目关联数据；没有对应后端能力时显示可创建/规划状态，绝不以全局数据冒充项目数据。
- 附件和知识页使用显式 `ObjectReference` 记录类型与 ID，而不是任意字符串 URL。
- 转换动作保留来源：情报、会议行动项、风险和知识页转为任务时记录 `sourceType`、`sourceId` 和转换时间。
- 软删除对象的关联只读可见，但不可作为新的关联目标；恢复后恢复原有引用。

## 阶段一：项目空间与我的工作

### 前端

- `/spaces/projects/:projectId/:section?` 实现概览、任务、进展、风险与问题、会议、资料六个真实页签。
- 概览显示项目基本信息、健康度、里程碑、临近任务和最近进展；每项点击进入同一项目上下文。
- 我的工作提供收件箱、今日、本周、日历和稍后处理视图；任务可完成、延期、设置提醒或移入稍后处理。
- 日历以月/周列表呈现任务截止日、会议时间和提醒；拖放不进入首批，修改日期采用明确表单。

### 后端

- 扩展项目聚合读取接口，按 projectId 返回现有任务、里程碑、进展和健康度；新增风险/问题/会议的项目筛选，严格验证关联对象存在且未归档。
- 新增 `TaskReminder` 与 `TaskLater` 本地表/API；提醒调度在应用打开时计算，不依赖云推送。
- 提供 `/my-work` 聚合和 `/calendar` 查询 API，统一按本机时区返回 ISO 时间。

### 验收

- 进入项目空间后，六个页签不会丢失项目上下文；错误、空状态和重试均可用。
- 我的工作、日历、提醒全部只显示真实任务/会议数据；关闭任务会同步工作台、项目和日历缓存。

## 阶段二：业务库与跨项目关联

### 前端

- 业务库首页成为多对象目录；每个对象库提供搜索、筛选、排序、分页/加载更多和详情工作区。
- 风险、问题、决策、合作方、申报、情报和非项目研发详情呈现字段、关联项目、来源记录、相关任务、会议和资料。
- 提供“关联到项目”“由此创建任务”“查看引用”的统一操作，所有操作完成后定位真实对象。

### 后端

- 统一 `Reference` 查询服务和对象详情 DTO；任何引用创建/更新校验类型、对象存在性和软删除状态。
- 为既有风险、问题、决策、会议、申报增加 projectId 筛选和必要索引；不改变已部署数据的主键或删除列。
- 为跨库检索提供受限字段、关键词、状态、时间和 projectId 筛选接口，避免前端全量拉取。

### 验收

- 任何业务对象可从项目空间跳转、从业务库反向回项目。
- 同一个对象在列表、详情和项目上下文显示一致；错误关联返回可读 400/404 而不是 Prisma 500。

## 阶段三：会议资料与知识库

### 前端

- 会议详情支持议程、纪要正文、行动项、决策、关联项目和附件；行动项转任务后展示来源链接。
- 附件支持选择文件、进度、下载、预览元信息、关联/解除关联、回收站恢复；不假定网络文件系统。
- 知识库采用目录树、知识页列表、正文编辑区三栏结构；支持新建、移动、归档、标签、模板、项目/会议/情报/任务/附件关联和反向引用。
- 正文首版使用受控 Markdown（标题、列表、链接、代码、引用、任务清单）；不引入实时协同编辑器。

### 后端

- 本地附件存储服务、文件元数据、对象引用、下载鉴权（本机 token）和回收站生命周期。
- `KnowledgeSpace`、`KnowledgeNode`、`KnowledgePage`、`KnowledgeTag` 与 `KnowledgeReference` Prisma 模型；节点移动必须防止循环父子关系。
- 用 PostgreSQL FTS 为标题、摘要和 Markdown 正文建立检索索引；搜索 API 返回命中摘要和对象引用，不暴露已归档正文。

### 验收

- 删除/恢复附件不破坏原对象；找不到文件会显示可修复状态而不是下载空文件。
- 知识页可编辑、保存、按目录和标签浏览、关联项目/会议等对象，并能从对象详情反查引用。

## 阶段四：行业情报与数据治理

### 前端

- 情报空间提供主题、来源、采集计划、情报卡、日报和转换面板；手动采集先于联网采集。
- 情报卡可转换为任务、风险、会议议题，且明确显示已转换记录，避免重复转换。
- 自动化与数据页提供全局搜索、提醒中心、CSV/Excel 导入导出、备份恢复、审计浏览。

### 后端

- 情报主题/来源/计划/卡片/日报模型和转换事务；去重键防止同一来源重复写入。
- 本地提醒规则、全局索引、导入预检/错误报告、可校验备份 manifest、恢复前快照、审计事件。
- Excel/CSV 仅接受白名单表头和大小限制；备份恢复验证 hash、文件集合、路径安全和数据库 schema 版本。

### 验收

- 每次情报转换和导入都可追溯来源、结果和错误行。
- 备份可验证、恢复失败可回滚；全局搜索不返回已归档或无访问资格的内容。

## 阶段五：研发运营、报表与桌面交付

### 前端

- 非项目研发记录、资源负荷、周/月报和项目组合报表；报表使用真实聚合数据，可导出。
- Electron 首次运行诊断、后端/数据库状态、存储目录、备份入口和本地通知偏好。

### 后端与桌面

- 非项目研发、工时/负荷、报表聚合 API 和可导出视图。
- Electron 负责本地后端生命周期、端口发现、数据库/存储诊断、安全 preload、打包 Prisma migrations 和应用升级边界。

### 验收

- 桌面包首次启动可诊断本机依赖并给出明确修复指引。
- 报表指标可追溯到项目、任务、会议、情报或非项目记录，不能用演示数字填充。

## 贯穿式质量要求

- 每个新增 API 先以 service/controller/integration 测试证明 RED，再写最小实现；迁移只前向新增，不清库。
- 每个新增页面以组件测试覆盖加载、空、错误、成功和关键转换；Playwright 覆盖项目→任务→会议/资料/知识的主路径。
- 前端提交前运行 `pnpm lint && pnpm typecheck && pnpm test && pnpm build`；后端提交前运行对应 unit、integration、Nest build 与 Prisma generate/migrate 检查。
- 子代理只处理不重叠文件集合；每项完成后先审规格、再审代码质量。用户要求的可见性优先：实现完成且验证通过的提交直接进入 `main`。

## 交付顺序与依赖

1. 阶段一先建立项目上下文和个人任务时间模型。
2. 阶段二把业务对象接入统一引用，供阶段三的会议、附件、知识页复用。
3. 阶段三先完成资料/知识基础，阶段四在此基础上实现情报转换和搜索/备份。
4. 阶段五最后打包 Electron，确保安装包承载已验证的数据模型和恢复流程。

任何阶段都不以页面占位作为完成标准；必须同时拥有 Prisma 迁移（若需要新数据）、后端 API、前端交互、自动化测试和可见的本机数据结果。
