# 文件型知识库与稳定性修复设计

## 1. 背景

当前知识库同时混用了“在线富文本文档”“附件管理”“本地文件同步”和“AI RAG”四种模型，导致职责不清：

- 上传后的文件正文被转换成纯文本展示，无法保留原文件格式。
- 富文本工具栏与用户实际需要的文件阅读场景不匹配。
- 本地文件和上传文件没有形成统一、可靠的查询源。
- 数据库 migration 依赖手工安装 PostgreSQL 扩展。
- 向量字段和 Embedding 服务存在，但生产检索仍然是关键词匹配。
- 文件扫描、重新索引、SSE 和测试配置存在稳定性问题。

本次修复将知识库统一为“文件型知识库”，以原文件为事实来源，以预览产物服务阅读，以提取文本和语义向量服务搜索与问答。

## 2. 产品定位

知识库不提供在线富文本正文编辑。用户通过以下两种方式建立知识来源：

1. 上传文件到工作台，由工作台托管原文件。
2. 选择本地文件夹，由工作台监听并索引本地文件，原文件继续保存在用户选择的位置。

知识库提供：

- 文件目录、收藏、标签、项目关联和最近访问。
- 原格式预览、下载原文件、调用系统应用打开。
- 文件名、正文、表格内容和标签搜索。
- 基于上传文件与本地文件的 AI 问答。
- 文件变化后的自动预览更新和重新索引。

不提供：

- 富文本正文编辑器。
- Markdown 格式工具栏。
- 将提取后的纯文本当成原文件正文保存。

## 3. 文件数据模型

每个知识文件由三类数据组成，互相独立：

### 3.1 原始文件

- 上传文件复制到工作台受控存储目录。
- 本地监听文件记录规范化绝对路径、文件指纹和最后修改时间。
- 原始文件始终是内容事实来源。
- 上传文件支持下载；本地文件支持调用系统应用打开。

### 3.2 预览产物

- PDF：直接使用原始 PDF。
- Word、PowerPoint、Excel：通过 LibreOffice headless 转换为 PDF 缓存。
- 图片：直接显示原图。
- Markdown、TXT、CSV、JSON、HTML：使用安全的专用只读渲染器。
- 无法预览的文件：显示文件信息，并提供系统打开或下载。
- 预览失败只影响在线预览，不影响原文件、搜索和下载。
- 预览缓存以文件哈希作为版本标识；文件变化后旧缓存失效。

Excel 第一阶段优先保证原始样式，使用 LibreOffice 分页预览。交互式工作表切换、筛选和单元格操作不在本次修复范围内。

### 3.3 搜索索引

- 从原文件独立提取标题、正文、页码、工作表名称、段落和表格文本。
- 分块记录必须携带文件 ID、页码或工作表、分块序号和来源类型。
- 上传文件和本地文件进入同一个索引管线。
- 预览转换失败时仍尝试文本提取和索引。

## 4. 检索与 AI 问答

### 4.1 检索策略

采用混合检索：

1. PostgreSQL 全文/`pg_trgm` 关键词召回。
2. 本地 Embedding 语义向量召回。
3. 按关键词分数、向量相似度和文件元数据进行合并排序。
4. 没有本地 Embedding 模型时降级为关键词检索，并在界面明确显示当前检索模式。

DeepSeek 只负责根据召回内容生成回答，不承担 Embedding。

### 4.2 本地 Embedding

- 使用可替换的 `EmbeddingProvider` 接口。
- 默认提供本地模型实现，模型文件保存在工作台缓存目录。
- 首次使用前显示模型未准备状态，不在后台静默下载大模型。
- 模型准备失败时保持关键词搜索可用。
- 向量维度由 provider 声明，数据库 migration 与当前 provider 保持一致。

### 4.3 查询范围

默认查询所有活跃的上传文件和本地监听文件，并支持：

- 按知识空间过滤。
- 按文件类型过滤。
- 按项目、标签过滤。
- 仅查询当前文件或当前目录。

回答引用必须显示文件名、来源类型以及页码、工作表或片段位置；点击引用打开对应文件预览。

## 5. 文件处理流程

### 5.1 上传文件

1. 校验扩展名、MIME、文件大小和文件签名。
2. 将原文件写入受控存储。
3. 在一个数据库事务中创建文件记录和知识文件记录。
4. 提交预览与索引后台任务。
5. API 立即返回文件 ID、名称和处理状态，不返回完整提取文本。
6. 前端通过状态接口或 Socket/SSE 获取处理进度。

### 5.2 本地文件夹

1. 用户选择文件夹并确认监听范围。
2. 初次扫描和后续文件事件通过同一任务队列处理。
3. 同一监听目录只允许一个全量扫描任务。
4. 同一文件只允许一个导入或更新任务。
5. 文件记录和知识文件必须在一个事务中创建，失败时不得留下孤立文档。
6. 文件删除后标记来源不可用，保留审计记录；索引立即停止参与查询。

所有文件 I/O 使用异步 API。扫描阶段只读取必要元数据，哈希、文本提取和预览转换在受控并发任务中执行。

## 6. 重新索引

- `POST /knowledge/reindex` 只创建任务并立即返回 `jobId`。
- 后台任务分批处理文件，不一次加载全部正文。
- 状态接口返回总数、已处理数、失败数、当前文件和错误摘要。
- 重复点击重新索引复用当前活动任务。
- 单个文件失败不终止整个任务。
- 索引状态持久化，后端重启后能够标识中断任务并重新执行。

## 7. SSE 与错误处理

- SSE 响应建立后不再修改 HTTP 状态码。
- 建立连接前发生错误时返回标准 HTTP 错误。
- 建立连接后发生错误时发送 `event: error` 并正常结束连接。
- 前端解析器跨网络分块保存事件类型和未完成数据。
- 用户停止回答时取消 DeepSeek 请求和服务端读取器。
- 没有召回片段时不调用 DeepSeek，直接返回空结果状态。

## 8. 配置

- 知识问答读取统一的扩展配置，不单独读取另一套页面不可见配置。
- 环境变量只作为首次启动或开发环境回退。
- AI Key 不写入 PostgreSQL、浏览器存储、日志、备份或响应。
- 聊天模型、Embedding provider、模型路径和检索模式均能显示当前状态。

## 9. 数据库迁移

- 在首次使用 `vector` 和 `pg_trgm` 的 migration 之前增加扩展 migration。
- 不修改已应用 migration 的校验内容。
- 新数据库执行 `prisma migrate deploy` 能从零完成。
- 现有数据库可以无数据损失地补充扩展和向量维度变更。
- 迁移测试需要在不预装扩展的临时数据库中运行。

## 10. 前端交互

知识库页面采用三栏文件阅读布局：

1. 左栏：知识空间、本地文件夹、收藏、回收站。
2. 中栏：文件列表、搜索、类型和标签过滤。
3. 右栏：文件预览、元数据、项目关联、引用位置和处理状态。

原来的富文本格式工具栏、正文输入状态和“保存正文版本”移除。文件版本改为上传新版本或本地文件版本变化记录。

预览区域必须区分：

- 正在转换。
- 可以预览。
- 转换失败但可以下载/打开。
- 原文件已经移动或删除。
- 文件内容已更新，正在重新索引。

## 11. 测试与验收

### 11.1 数据库

- 全新 PostgreSQL 数据库不预装 `vector`、`pg_trgm` 时迁移成功。
- 扩展、向量列和索引存在。
- 现有数据迁移后仍可读取。

### 11.2 后端

- 上传文件不返回完整纯文本。
- 文件记录和知识记录事务一致。
- 同一文件并发事件不会产生重复或孤立记录。
- 重建索引接口立即返回任务 ID。
- 无匹配内容时不请求 DeepSeek。
- SSE 建连前后错误均返回正确协议。
- 上传文件和本地文件都能被搜索及引用。

### 11.3 前端

- 不再显示富文本工具栏。
- PDF、Office、图片和文本类文件进入正确预览器。
- 预览失败仍能下载或系统打开。
- SSE 事件被拆分到多个网络包时仍能正确解析。
- 搜索结果能打开引用文件及定位信息。

### 11.4 工程基线

- 后端 build、lint、unit、integration 通过。
- 前端 lint、typecheck、unit、build 通过。
- Chokidar 与 Jest 模块模式兼容。
- 后端在项目声明的 Node 版本中无实验性模块加载警告。

## 12. 实施顺序

1. 修复测试基线和数据库扩展 migration。
2. 重构文件数据模型及上传响应。
3. 建立预览服务和缓存。
4. 串行化文件扫描并改为异步 I/O。
5. 建立持久化索引任务。
6. 接入本地 Embedding 和混合检索。
7. 修复 SSE 与统一 AI 配置。
8. 重构知识库文件阅读界面。
9. 执行全量测试和全新数据库验收。
