# 项目进度联动与 AI 知识助手设计规格

日期：2026-07-28  
状态：设计已确认，待实施计划  
适用项目：`rd-manager-workbench`

## 1. 背景

当前项目详情中的里程碑、工作项、进展记录和项目总进度彼此相对独立：

- 项目总进度取最新一条手工进展记录中的百分比，不能真实反映工作项完成情况。
- 里程碑只有单一计划时间和状态，没有计划时间段、权重和完成比例。
- 任务虽然可以关联里程碑并记录完成率，但没有参与里程碑和项目进度计算。
- 时间消耗和实际完成度没有并列呈现，用户无法快速判断项目提前或滞后。
- AI 问答以局部弹窗和简单对话区域为主，知识范围、引用来源和连续追问关系不清晰。

本次改造把项目进度变成可追溯的计算结果，并将 AI 问答升级为以本地文件和上传文件为知识源的三栏知识助手工作区。

## 2. 目标

### 2.1 项目进度

- 项目总进度由里程碑进度按权重汇总。
- 里程碑优先根据关联工作项自动计算进度。
- 项目周期、里程碑计划时间、实际进度和时间进度在同一条周期轨道上展示。
- 工作项或里程碑变化后自动生成进展记录，保留计算依据。
- 手工进展记录承担阶段总结职责，不再直接覆盖项目总进度。

### 2.2 AI 知识助手

- 问答内容只使用已纳入知识库且完成索引的本地文件、扫描同步文件和上传文件。
- 支持持续对话、明确的检索范围、流式响应和可追溯引用。
- 点击引用时在当前页面右侧预览原文片段，不中断对话。
- 提供接近飞书知识助手的清晰三栏布局和完整反馈状态。

## 3. 非目标

- 本次不实现多人协同、权限审批和实时共同编辑。
- 本次不继续开发 Office 文件的保真原格式预览。保留原文件下载和已有降级展示能力。
- 本次不引入互联网搜索；AI 不得使用知识库之外的网页内容补充答案。
- 本次不引入工作项权重。一个里程碑下的有效工作项默认等权计算。
- 本次不改变短信通知、外部日历和云盘集成范围。

## 4. 核心概念与计算规则

### 4.1 里程碑计划时间

里程碑由单个 `plannedAt` 扩展为：

- `plannedStartAt`：计划开始时间，可为空。
- `plannedEndAt`：计划结束时间，可为空。
- `actualAt`：实际完成时间，沿用现有字段。

迁移旧数据时，如果旧 `plannedAt` 有值，则同时写入新的 `plannedEndAt`；`plannedStartAt` 保持为空，避免虚构开始时间。兼容期内后端仍可读取旧字段，但新接口和新页面只使用时间段字段。

### 4.2 里程碑权重模式

项目支持两种权重模式：

1. **平均权重（默认）**：系统根据有效里程碑数量自动平均分配，用户不需要逐项维护。
2. **自定义权重**：用户为每个有效里程碑设置权重，保存时总和必须为 100%。

有效里程碑是未删除且未取消的里程碑。平均权重计算使用高精度数值，页面可显示整数或一位小数；最后一个里程碑承担展示舍入差额，保证页面合计为 100%。

自定义权重不满足 100% 时：

- 编辑页面显示当前合计和差额。
- 禁止保存权重配置。
- 已保存项目的历史进度继续使用上一次有效权重，不产生临时错误进度。

### 4.3 里程碑进度

里程碑完成率的优先级如下：

1. 状态为 `COMPLETED`：完成率固定为 100%。
2. 存在有效关联工作项：取工作项 `completionPercent` 的算术平均值。
3. 没有关联工作项：使用里程碑的手工完成率 `manualCompletionPercent`。
4. 没有任何有效数据：完成率为 0%。

有效工作项不包括已删除或已取消的工作项。工作项完成率统一限制在 0–100 之间。

公式：

```text
里程碑进度 = Σ（有效工作项完成率）÷ 有效工作项数量
```

当里程碑存在关联工作项时，页面禁用手工完成率输入，并说明“当前进度由 N 个工作项自动计算”。移除全部工作项后，恢复手工录入能力。

### 4.4 项目实际进度

项目实际进度由有效里程碑加权汇总：

```text
项目实际进度 = Σ（里程碑完成率 × 里程碑有效权重）
```

如果项目没有有效里程碑：

- 项目进度显示为“未规划”，不显示虚假的 0% 环形进度。
- 页面提供“创建里程碑”操作。
- 工作项完成率不直接替代项目进度。

后端计算保留至少四位小数，接口返回两位小数，页面默认显示取整百分比。

### 4.5 项目时间进度

项目计划开始和计划结束时间均有效且结束时间晚于开始时间时：

```text
时间进度 = (当前时间 - 计划开始时间) ÷ (计划结束时间 - 计划开始时间)
```

结果限制在 0–100%：

- 项目尚未开始：0%。
- 项目计划周期内：按实际时间比例。
- 已超过计划结束时间：100%。

进度偏差：

```text
进度偏差 = 项目实际进度 - 时间进度
```

- 偏差大于等于 5 个百分点：标记“领先”。
- 偏差在 -5 到 5 之间：标记“正常”。
- 偏差小于等于 -5 个百分点：标记“滞后”。

阈值作为前后端共享配置，后续可以开放到设置页面。项目周期缺失或异常时不计算时间进度，并提示补充计划周期。

## 5. 进展记录设计

### 5.1 记录类型

进展记录增加来源类型：

- `MANUAL`：用户主动填写阶段总结。
- `TASK_CHANGE`：工作项完成率、状态或里程碑关联发生变化。
- `MILESTONE_CHANGE`：里程碑状态、手工完成率或权重发生变化。
- `SYSTEM_RECALCULATION`：数据迁移、恢复或批量操作触发重新计算。

### 5.2 记录内容

每条记录至少保存：

- 发生时间。
- 来源类型。
- 变更前项目进度。
- 变更后项目进度。
- 关联里程碑 ID，可为空。
- 关联工作项 ID，可为空。
- 摘要。
- 阻塞问题，可为空。
- 下一步计划，可为空。
- 触发对象和变更字段的结构化快照。

系统记录由后端在业务事务成功后写入。只在项目展示进度发生变化时生成，重复写入同一数值不创建噪声记录。

### 5.3 手工进展

手工进展表单包含：

- 阶段总结，必填。
- 关联里程碑，可选。
- 已完成成果，可选。
- 阻塞问题，可选。
- 下一步计划，可选。
- 记录时间，默认当前时间。

表单展示提交时的项目实际进度快照，但不允许手工覆盖计算结果。

## 6. 项目详情交互设计

### 6.1 概览

概览顶部显示：

- 项目实际进度。
- 时间进度。
- 领先、正常或滞后状态。
- 当前里程碑。
- 计划结束时间和剩余天数。

项目进度和时间进度使用不同颜色和明确文字，不只依赖颜色传达含义。

### 6.2 周期轨道

采用已确认的“周期轨道”方案：

- 轨道范围与项目计划周期一致。
- 每个里程碑显示计划开始与结束时间、完成率、权重和状态。
- 已完成节点使用完成标记，当前节点突出显示，未开始节点保持中性。
- 点击节点打开里程碑详情抽屉，而不是离开项目工作区。
- 当前日期、实际进度位置和计划时间位置可在同一轨道对比。

### 6.3 里程碑列表与编辑

里程碑列表补充：

- 计划时间段。
- 自动或手工进度来源。
- 完成率进度条。
- 权重。
- 关联工作项数量。
- 负责人和状态。

里程碑表单补充计划开始、计划结束、权重模式下的权重和手工完成率。所有日期统一使用项目现有 UI 组件库的日期时间组件。

### 6.4 进展页签

进展页签展示：

- 项目实际进度与时间进度趋势。
- 按时间倒序的进展时间线。
- 系统记录与手工记录过滤。
- 按里程碑过滤。
- 每条记录的进度变化、来源对象和详细说明。

## 7. AI 知识助手交互设计

### 7.1 页面结构

采用已确认的三栏“知识助手工作区”：

1. 左栏：会话管理。
2. 中栏：对话与输入。
3. 右栏：引用原文预览。

右栏可折叠。窗口宽度不足时改为右侧抽屉，不能挤压主对话到不可读宽度。

### 7.2 会话管理

左栏支持：

- 新建对话。
- 最近会话列表。
- 会话标题搜索。
- 自动生成标题。
- 手工重命名。
- 收藏或置顶。
- 删除前二次确认。

切换会话时保留各自的知识范围和消息历史。

### 7.3 知识范围

每个会话必须有显式检索范围：

- 全部知识。
- 当前项目。
- 指定知识目录。
- 指定文件。
- 最近使用文件。

范围选择器显示文件数量和索引状态。没有可用文件时禁止发送，并提供上传文件或扫描目录入口。

### 7.4 问答流程

1. 用户选择或确认知识范围。
2. 输入问题并发送。
3. 页面显示“正在检索 N 个文件”。
4. 后端返回命中的文件和片段数量。
5. 页面流式展示回答。
6. 回答中的结论使用 `[1]`、`[2]` 等行内引用。
7. 点击引用后右栏定位到对应文件、页码或段落。

输入区支持：

- 自动增高。
- `Enter` 发送，`Shift + Enter` 换行。
- 生成中停止。
- 添加指定文件。
- 切换知识范围。
- 失败后重试。

回答操作支持：

- 复制。
- 重新生成。
- 编辑原问题后重新提问。
- 继续追问。
- 根据回答创建任务。

### 7.5 引用预览

引用预览显示：

- 文件名和文件类型。
- 命中页码、工作表、幻灯片或段落位置。
- 与问题相关的原文片段。
- 命中关键词高亮。
- 打开知识文档详情。
- 下载原文件。

“打开详情”由用户主动触发，默认点击引用不离开对话。

### 7.6 空状态和错误状态

空会话展示基于当前知识范围生成的建议问题，例如：

- 汇总本周项目进展。
- 列出最近会议的行动项。
- 查找当前项目的主要风险。
- 对比两个版本文档的关键变化。

错误必须区分：

- 文件尚未完成索引。
- 未检索到有效依据。
- 本地 AI 服务不可用。
- 流式连接中断。
- 引用文件已移动或删除。

没有有效依据时，回答固定说明“当前知识范围内未找到足够依据”，不得生成无引用结论。

## 8. 后端设计

### 8.1 领域服务

新增独立的项目进度计算服务，负责：

- 计算里程碑进度。
- 解析平均或自定义权重。
- 计算项目实际进度和时间进度。
- 生成进度差异状态。
- 生成幂等的系统进展记录。

项目、里程碑和工作项写操作统一在事务中完成业务更新；事务成功后触发一次项目进度重算。批量导入或恢复时只在批次结束后重算，避免为每一行创建记录。

### 8.2 API 响应

项目详情接口增加计算摘要：

```json
{
  "progressSummary": {
    "actualPercent": 56,
    "timePercent": 64,
    "variancePercent": -8,
    "scheduleState": "BEHIND",
    "weightMode": "EQUAL",
    "currentMilestoneId": "..."
  }
}
```

里程碑响应增加：

```json
{
  "plannedStartAt": "2026-05-21T00:00:00.000Z",
  "plannedEndAt": "2026-08-15T00:00:00.000Z",
  "effectiveWeightPercent": 35,
  "completionPercent": 68,
  "completionSource": "TASKS",
  "linkedTaskCount": 6
}
```

AI 问答流式事件至少区分：

- `retrieval_started`
- `retrieval_completed`
- `answer_delta`
- `citation`
- `completed`
- `failed`

每个引用包含稳定的文档 ID、片段 ID、位置元数据和显示文本，前端不得通过回答文本猜测引用位置。

## 9. 数据迁移与兼容

- 新字段必须提供可回滚的数据库迁移。
- 旧 `plannedAt` 迁移到 `plannedEndAt`，原字段在一个兼容周期内保留。
- 现有里程碑项目默认使用平均权重。
- 现有进展记录标记为 `MANUAL`，原百分比保留为历史快照，但不参与新的项目进度计算。
- 首次打开项目详情时可以按需重算；迁移脚本也应支持一次性批量重算。
- 重算失败不得阻断项目基础信息读取，接口返回明确的降级状态和 trace ID。

## 10. 性能与一致性

- 同一项目的进度计算必须使用同一事务快照中的里程碑和工作项数据。
- 项目列表使用预计算摘要或批量查询，禁止逐个项目产生 N+1 查询。
- AI 会话列表、消息和引用分开分页，避免一次加载所有历史内容。
- 对话流式更新只增量修改当前回答，不重新渲染整页文档列表。
- 引用原文按需加载并缓存，切换引用时取消过期请求。

## 11. 验收标准

### 11.1 项目进度

- 修改工作项完成率后，关联里程碑和项目总进度同步更新。
- 完成里程碑后，该节点显示 100%，项目总进度按权重更新。
- 无工作项里程碑可手工维护进度；一旦关联工作项，切换为自动计算。
- 平均权重与自定义权重计算结果符合公式。
- 自定义权重不等于 100% 时不能保存。
- 项目时间进度与计划周期一致，异常周期不会产生错误百分比。
- 系统进展记录能追溯到触发的工作项或里程碑。
- 手工进展不能覆盖项目计算进度。

### 11.2 AI 知识助手

- 可以在全部知识、当前项目、目录和指定文件范围之间切换。
- 未完成索引的文件不会作为回答来源。
- 回答具有行内引用，点击引用在右侧展示对应原文。
- 查看引用不会丢失当前对话。
- 支持连续追问、停止生成、重试、复制和重新生成。
- 无有效依据时不生成无引用答案。
- 窄屏下引用栏变为抽屉，主对话仍可正常使用。

## 12. 测试策略

- 领域单元测试覆盖里程碑进度、权重、项目进度、时间进度和边界值。
- 后端集成测试覆盖任务更新事务、自动进展记录、迁移兼容和批量重算。
- 前端组件测试覆盖权重编辑、周期轨道、进度来源提示、知识范围和引用抽屉。
- API 契约测试覆盖新增字段和 AI 流式事件。
- 端到端测试覆盖“创建项目周期 → 创建里程碑 → 关联任务 → 完成任务 → 查看进度变化”。
- 端到端测试覆盖“选择知识范围 → 提问 → 查看流式回答 → 点击引用 → 连续追问”。
- 视觉回归测试覆盖项目概览、里程碑编辑、进展页签和 AI 三栏工作区。

## 13. 实施边界

实施计划应拆分为可独立验证的阶段：

1. 数据模型、迁移和进度计算领域服务。
2. 里程碑、工作项和进展记录接口联动。
3. 项目详情周期轨道和表单改造。
4. AI 会话、检索范围和引用协议。
5. AI 三栏工作区前端。
6. 数据迁移、端到端验证和视觉验收。

每一阶段必须先补充失败测试，再实现生产代码；不得将 Office 保真预览工作混入本次范围。
