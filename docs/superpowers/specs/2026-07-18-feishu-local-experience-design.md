# 本地单人飞书式研发工作台设计

## 目标

将研发主管工作台组织为“飞书式工作空间”体验：左侧工作台导航、中心任务/资料/动态内容区、对象详情工作区与统一快捷入口。第一期仍完全本地、单人和 PostgreSQL 存储；不实现账号、组织、群聊、多人协作、云同步或第三方飞书 API。

## 设计原则

- 采用信息密度高、可快速切换的工作台，而非传统后台菜单加孤立表单。
- 用研发领域对象替代飞书通用对象：项目空间、申报档案、风险、会议、情报和资料是核心载体。
- 任何行动都可溯源：任务保留会议、决策、沟通、风险或情报来源；附件、提醒、审计贯穿对象。
- 所有数据本地持久化，界面不假定联网、用户登录或另一个协作者存在。
- 借鉴信息架构和交互节奏，不复制飞书品牌、视觉资产或专有内容。

## 信息架构

左侧导航固定为以下分组，并允许后续扩展：

1. **工作台**：今日待办、临期、待决策、未关闭高风险、近期会议、情报摘要、快捷新建。
2. **项目空间**：项目卡片/列表进入单一对象工作区，包含概览、任务、进展、风险、会议、资料和关联情报。
3. **申报认定**：案件、流程、条件、材料版本、证据、补正和提交时间线。
4. **管理闭环**：风险、问题、决策、合作方、沟通、会议和行动项；对象之间相互关联并可生成任务。
5. **行业情报**：主题、来源、手动采集、情报卡、日报/周报和转换操作。
6. **数据中心**：附件库、提醒、全局搜索、导入导出、备份恢复和审计。
7. **设置**：本机数据库、存储目录、通知和界面偏好。

## 页面与交互

- 首页采用三列或自适应卡片流：左侧“今日行动”，中部“项目/风险状态”，右侧“会议、情报和快捷创建”。
- 列表页同时支持检索、状态筛选、密集行视图和空状态引导；不显示仅为占位的静态数据。
- 对象详情采用二级页签/侧栏：概要在最前，关联任务、文件、动态记录在相邻页签；写操作在上下文中完成。
- 新建入口统一使用对话框或轻量侧栏，创建后自动定位到新对象并刷新相关工作台卡片。
- 完成、归档、转换等动作总显示结果与失败原因；不会静默丢失关联关系。

## 功能映射

| 飞书式使用体验 | 本地研发工作台实现 |
| --- | --- |
| 工作台待办与消息流 | 今日行动、提醒、项目健康度、会议和情报摘要 |
| 多维表格/对象库 | 项目、任务、风险、决策、案件、情报的可筛选列表 |
| 文档与知识沉淀 | 附件索引、材料版本、会议纪要、证据与项目资料 |
| 日程/会议协作 | 本地会议、议程、纪要、行动项与任务转换 |
| 审批/工作流 | 申报流程模板、节点校验、材料版本和提交记录 |
| 机器人自动化（后续） | 本地提醒、日报生成、导入导出和规则触发；不依赖云端推送 |

## 明确不在第一期范围

- 账号、组织架构、角色/权限、SSO 和审计管理员后台。
- 群聊、即时消息、@提及、在线状态、协同编辑、评论线程与多人冲突处理。
- 跨设备同步、云端部署、飞书开放平台/机器人、OAuth、日历或网盘双向同步。
- AI 自动摘要、联网爬虫和外部项目系统同步；这些仍属于 P2 扩展。

## 验收与测试

- 每个已实现模块必须有左侧入口、加载/空/错误状态和真实 API 数据。
- 业务对象详情至少呈现其核心字段、关联任务和时间线/记录入口；无法实现的关联不得伪造。
- 前后端接口保持 `/api`、统一响应包和本机 CORS 限制；新增行为先写失败测试。
- 用组件测试覆盖导航、空状态、转换动作失败反馈；用后端集成测试覆盖对象关联与来源追溯。
