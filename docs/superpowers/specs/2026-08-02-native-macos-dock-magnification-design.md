# 原生感 macOS 竖向 Dock 放大修正规格

## 1. 修正目标

当前 Dock 只改变图标尺寸，并用纵向位移把相邻图标拉向指针；它没有形成 macOS 左侧 Dock 的横向凸出和沿主轴让位，因此视觉上只是原地放大。本次修正把交互升级为二维鱼眼布局：指针所在位置形成放大峰值，邻近图标连续衰减，整组图标向内容区凸出，上下图标分别向两侧让位。

本次同时替换统一渐变底板图标。每个模块改为独立的应用图标构图和材质，保留统一的超椭圆轮廓、阴影质量和视觉尺寸，但不再共享同一套高光矩形与白色线框。

## 2. 参考依据

- Apple 的桌面与 Dock 设置支持左侧 Dock，并把普通尺寸和放大尺寸作为独立参数；设备管理文档给出的最大放大尺寸范围为 16～128px。
- Motion 官方建议用共享 `MotionValue` 表示指针位置，通过 `useTransform` 派生多个视觉值，并使用 `useSpring` 保持连续响应而不触发 React 重渲染。
- `react-osx-dock` 的公开源码按图标中心距计算强度，并使用三个基础图标宽度作为作用半径；本项目沿用“中心距 + 三格作用范围”这个结构，但使用更平滑的余弦衰减。
- 公开 SwiftUI Dock 示例使用短响应、低延迟的弹簧。本项目保留 Framer Motion，并通过浏览器逐帧测量调节阻尼，目标是快速跟手、离开后无残余振荡。

## 3. 二维鱼眼运动模型

### 3.1 稳定坐标

- `WorkspaceNavigation` 继续持有共享指针纵坐标。
- 每个 `DockItem` 使用未应用 transform 的基础中心计算距离，不能读取已位移元素的 `getBoundingClientRect()` 作为下一帧输入。
- 基础中心使用 Dock 容器坐标和元素 `offsetTop`/稳定槽位中心计算，消除自反馈、跳动和波峰漂移。
- 指针离开 Dock 时使用 `Infinity` 表示无影响，所有派生值通过同一组 spring 回到基础状态。

### 3.2 尺寸峰值

设：

- `d` 为图标基础中心与指针的有符号距离。
- `R` 为影响半径，常规模式为三个基础槽位，紧凑模式同样覆盖约三个图标。
- `t = clamp(abs(d) / R, 0, 1)`。
- `w = cos(t * PI / 2) ^ 2`，作用范围外 `w = 0`。

图标尺寸：

`size = baseSize + (maxSize - baseSize) * w`

常规模式使用约 46px 基础尺寸和 92px 峰值；紧凑模式使用约 40px 基础尺寸和 78px 峰值。最终数值允许在浏览器测量后小幅调整，但必须保持接近 2 倍的中心峰值。

### 3.3 向内容区凸出

左侧 Dock 的图标必须向右凸出，而不是以轨道中心向两边平均增长。横向位移由图标增长量和曲线强度共同决定：

`outwardX = (size - baseSize) / 2 + outwardBoost * w`

第一项基本固定放大图标的左侧视觉边缘，第二项形成额外的弧形凸出。中心图标横向位移最大，第一、第二邻居依次减少，作用范围外为 0。

### 3.4 主轴让位

相邻图标不能被放大图标覆盖。让位方向必须背离指针：指针上方的图标向上移动，指针下方的图标向下移动。

让位采用累计扩张曲线：

- 峰值中心的纵向位移接近 0。
- 距离越远，累计让位越大，直到作用范围边界达到稳定偏移。
- 作用范围外图标保持基础尺寸，但继承波峰造成的最终偏移，使整列 Dock 在波峰两侧自然展开。
- 位移符号与 `d` 相同，禁止再次使用当前的 `-sign(d)`。

纯函数需要同时返回：

```ts
interface DockMotionResult {
  size: number
  outwardX: number
  spreadY: number
  influence: number
}
```

### 3.5 弹簧响应

- 尺寸、横向凸出、纵向让位分别使用 spring，但共享同一目标曲线。
- 起始参数使用短响应、高阻尼范围，浏览器实测目标为快速跟手且复位不摆动。
- 快速从第一个图标扫到最后一个图标时，波峰连续移动，不允许出现逐项补间、图标追赶或闪烁。
- `prefers-reduced-motion` 下返回基础尺寸、零横向位移和零纵向位移。

## 4. 图标视觉

九个模块使用九套独立 SVG 应用图标：

1. 工作台：深蓝工作区窗口与高亮面板。
2. 我的工作：暖白底的彩色任务清单与完成标识。
3. 项目：蓝色立体文件夹与项目卡片。
4. 员工：绿色人物协作图形。
5. 文档与知识库：白色纸张、蓝色书脊和知识标记。
6. 多维表格：青色数据表格和层叠单元格。
7. 日历：白色日历页、红色页眉和清晰日期。
8. 搜索：浅色底的蓝色放大镜与彩色检索光点。
9. 系统管理：银灰机械齿轮和内层控制盘。

共同约束：

- 使用项目自有图形，不复制 Safari、微信、Chrome 等第三方图标。
- 每个图标可以使用不同底色、层次与内部形状，不再套统一渐变模板。
- 统一使用接近 macOS 应用图标的连续圆角轮廓、轻边缘高光和自然下投影。
- 图形必须在 40px 时仍能辨认，在约 92px 放大后不能暴露粗糙线条或空洞细节。

## 5. 组件调整

### `dock-motion.ts`

- 改为输出完整二维鱼眼结果。
- 距离衰减、横向凸出和主轴让位均为可单测纯函数。
- 常规、紧凑指标包含峰值尺寸、外凸增强量和最大让位量。

### `DockItem.tsx`

- 使用稳定基础中心计算距离。
- 同时绑定 `width`、`height`、`x` 和 `y` spring。
- 命中区域继续使用固定槽位，不能随图标外凸而丢失 hover。
- Tooltip 跟随实际图标右边缘显示，避免被放大图标覆盖。

### `WorkspaceDockIcon.tsx`

- 删除共享的 `palette + 通用背景矩形 + 通用高光矩形` 模板。
- 每个 `NavigationIcon` 输出独立完整 SVG 构图。
- 统一的阴影和超椭圆裁切由外层样式负责。

## 6. 测试与验收

### 自动化

- 先写失败单测，验证中心峰值、第一/第二邻居连续递减、横向外凸递减和上下让位方向。
- 验证作用范围外尺寸恢复正常，但主轴保留累计让位。
- 验证 reduced-motion 返回完全静态结果。
- 组件测试验证 `DockItem` 同时绑定 `x`、`y` 和尺寸，并继续保持真实链接语义。
- Playwright 在 1280×720、1280×600 下测量实际矩形：中心图标最宽、最近邻次宽、第二邻居再次变小；中心图标右边缘必须明显越过基础 Dock 轨道。

### 视觉验收

- 鼠标划过时能够直接看到一条向右凸出的平滑弧线，而不是一列原地放大的方块。
- 波峰中心最大，上下图标按距离连续变小，至少覆盖两个邻居后回到正常尺寸。
- 上方图标向上让位、下方图标向下让位，图标间不发生明显覆盖。
- 快速移动时动画跟手、平顺，离开后自然复位且无抖动。
- 所有图标看起来是不同的应用图标，不再像同一按钮换了颜色和线稿。

## 7. 非范围与边界

- 不复制 Apple 或其他软件厂商受版权保护的图标资源。
- 不改变现有路由、权限过滤、顶部 Header、页面功能和后端接口。
- 不为追求动画而改用 Canvas；DOM 链接语义、键盘访问和 Tooltip 必须继续保留。
- “与 macOS 一致”指可观察到的放大、外凸、让位、衰减与弹簧响应一致，不声称获得或复制 Apple 未公开的 Dock 内部实现源码。
