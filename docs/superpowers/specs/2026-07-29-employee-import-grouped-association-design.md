# 员工周报导入按员工分组与默认值设计

## 背景

V2 周报中的每名员工会产生多条本周工作和下周计划。当前补全弹窗把员工关联草稿放在每一条工作行上，导致同一姓名重复出现“选择员工”“按表内姓名新建”“将新建”等控件。后端会在同一批次内按标准化姓名复用员工，但前端展示仍容易让用户误以为会创建重复员工，并要求重复操作。

## 目标

- 同一标准化姓名只需要设置一次员工关联，自动应用到该员工的全部工作和计划。
- 已被预检匹配的员工默认使用 `resolvedEmployeeId`。
- 未匹配员工默认使用表内姓名新建档案，用户仍可改为关联现有员工。
- 同一员工的“新建/取消新建”和“同步部门/工作方向”决定在全部对应行保持一致。
- 工作事项仍逐行展示和编辑，工作类型、项目、任务、工时与风险不进行不可靠的自动推断。
- 提交请求仍只为同一标准化姓名发送一次 `createEmployee`，其他行由后端复用该员工。

## 交互设计

1. 表格继续按工作事项逐行展示。
2. 员工列按当前筛选结果合并相邻的同名行，只在分组首行展示员工控件。
3. 分组员工控件展示该姓名对应的工作条数。
4. 选择员工时，同名组全部行写入相同 `employeeId`，并清除新建状态。
5. 未匹配员工初始即显示“将新建：姓名”，点击“改为关联现有员工”后显示员工选择框。
6. 点击取消新建时，同名组全部行同步取消；重新启用新建时也同步。
7. 档案同步复选框按员工组联动。
8. 工作表/区域筛选后，合并行数依据当前可见行重新计算。

## 默认值规则

| 字段           | 默认值                                      |
| -------------- | ------------------------------------------- |
| 员工           | 优先使用后端预检返回的 `resolvedEmployeeId` |
| 未匹配员工     | 默认按表内姓名新建                          |
| 部门、工作方向 | 新建员工时使用表内值                        |
| 工作类型       | 后端已有值时保留，否则人工选择              |
| 项目、任务     | 后端已有关联时保留，否则人工选择            |
| 工时           | 保留导入/暂存值，缺失不填 0                 |
| 风险决定       | 保留预检结果，不额外自动修改                |

不把所有工作默认设为“非项目工作”，因为这会掩盖真实项目关联。

## 数据与安全

- 员工分组键使用 NFKC、去首尾空格、合并连续空白并转小写后的姓名。
- 前端分组联动只更新草稿，不提前写数据库。
- `toResolutions` 继续确保同一姓名只有第一条提交 `createEmployee`。
- 后端现有员工复用与重复姓名冲突校验保持不变。

## 验收标准

- 两条及以上同名工作只出现一个员工操作区。
- 未匹配员工无需逐行点击即可进入“将新建”状态。
- 切换员工、新建状态或档案同步后，同名全部行校验同步通过。
- 不同员工互不影响。
- 筛选后员工列合并正确。
- 提交中同名员工只有一条 `createEmployee`。
- 既有工作类型、项目任务、工时、风险与筛选测试继续通过。
