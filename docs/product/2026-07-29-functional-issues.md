## 1. 判定规则

本清单只收录以下三类问题：

1. 已有功能在特定环境或操作顺序下会失败、丢状态或显示错误结果。
2. 产品规格承诺了完整闭环，但当前只完成了入口、列表或一半流程。
3. 功能代码已存在，但缺少正式桌面环境或 Windows 环境的可重复验收，无法判定为稳定可交付。

“以后可能有用”的新功能不放在本清单中。

## 3. P0：阻塞核心使用的功能问题

### FUNC-P0-001 多维表格视图保存存在并发覆盖

**现状**

- 用户连续修改排序、筛选或手动保存视图时，较早的异步保存可能覆盖较新的配置。
- 2026-07-29 独立复跑回归用例仍稳定失败：预期保存 `score desc`，实际最终提交为旧的 `score asc`。

**影响**

- 用户看到的新视图配置与数据库保存结果不一致。
- 重新进入页面后，排序、筛选或字段配置可能“恢复成旧值”。
- 这是数据一致性问题，不能用提示或重试掩盖。

**证据**

- `frontend/src/modules/base/hooks.ts`
- `frontend/src/pages/LibraryHomePage.tsx`
- `frontend/src/modules/base/__tests__/ViewSettings.test.tsx:669`

**完成标准**

- 同一视图的保存严格串行，最后一次用户操作一定是最终状态。
- 手动保存、自动保存、切换视图和页面卸载必须共用同一保存队列。
- 保存失败只回滚失败操作，不得覆盖失败之后的新草稿。
- 相关测试全绿，并增加“快速连续修改 + 切换视图 + 卸载”组合回归。

### FUNC-P0-002 Electron 正式包中的知识库直连请求基址错误

**现状**

- 通用 `request()` 会读取运行时 `apiBaseUrl`，但以下功能绕过了通用请求层：
  - NOVA 流式问答；
  - 知识文件上传；
  - 本地文件夹扫描 SSE。
- 这些代码在非开发环境把 API 基址设为空。Electron 使用 `file://` 打开页面时，会形成错误的本地文件 URL。

**影响**

- 浏览器开发环境可用，正式桌面包中可能出现“无法问答”“上传失败”或扫描进度只能轮询降级。
- 同一功能在 Mac 开发环境和 Windows 安装包中的行为不一致。

**证据**

- `frontend/src/modules/knowledge/api.ts`
- `frontend/src/pages/KnowledgeHomePage.tsx`
- `frontend/src/modules/knowledge/components/KnowledgeFolderSync.tsx`
- `frontend/src/lib/http.ts` 已有正确的统一运行时基址逻辑，但上述链路未复用。

**完成标准**

- 流式请求、上传、下载和 SSE 全部通过同一个运行时 API URL 解析器。
- 增加 `file://` 页面环境下的 URL 单元测试。
- Electron 目录包实测完成一次上传、一次问答、一次文件夹重扫并收到实时进度。

### FUNC-P0-003 首次启动没有数据库初始化与修复向导

**现状**

- Electron 启动 NestJS 后只轮询健康接口。
- 未自动检查 PostgreSQL 服务、角色、数据库、schema、Prisma migration 和存储目录。
- 健康检查失败后仍会创建主窗口，用户通常只能继续看到“无法读取本地工作台”。

**影响**

- 新电脑或重装环境无法完成自助启动。
- 启动失败原因不明确，用户需要手工执行 Prisma 和数据库命令。

**证据**

- `desktop/src/main.ts` 中的 `startBackend()`、`waitForBackend()` 和 `app.whenReady()`。

**完成标准**

- 首次启动先执行环境预检，再创建业务窗口。
- 能区分 PostgreSQL 未安装、服务未启动、数据库不存在、迁移未部署、端口冲突和目录不可写。
- 可自动执行安全的建库与 migration；需要管理员权限的动作给出明确操作指引。
- 修复成功后自动重试，不要求用户重启应用。

### FUNC-P0-004 本地文件夹扫描进度不真实，错误恢复不完整

**现状**

- 页面能显示已扫描文件数，但扫描阶段的进度条固定为 `35%`。
- SSE 失败后会轮询，但没有显示“正在使用轮询补偿”。
- 当前只显示当前文件和最终数量，缺少发现文件总数、成功/跳过/失败分类和失败文件清单。

**影响**

- 大目录扫描时用户无法判断是否卡住、还要多久、哪些文件失败。
- 重新扫描失败后缺少明确的重试范围和修复入口。

**证据**

- `frontend/src/modules/knowledge/components/KnowledgeFolderSync.tsx`
- `backend/src/modules/workbench/knowledge/application/folder-watch.service.ts`

**完成标准**

- 扫描阶段先显示不确定进度，得到总数后切换为真实百分比，不能写死数值。
- 实时显示：发现、待处理、成功、更新、跳过、删除、失败。
- 失败文件可展开查看原因，并支持“只重试失败项”。
- 页面刷新或断线重连后可恢复当前任务进度。

### FUNC-P0-005 Windows 正式使用缺少完整平台验收

**现状**

- 本地语义模型已有原生运行时与 WASM 降级代码，但尚未在目标 Windows 安装包完成全链路验收。
- 备份/恢复依赖 `pg_dump`、`pg_restore`，当前主要依赖系统 PATH。
- Electron 资源中包含 Prisma、图像和 ONNX 等平台相关依赖，必须在 Windows 上构建和验证。

**影响**

- 用户已经在 Windows 上运行项目，模型、备份或原生模块可能出现“开发机正常、目标机失败”。
- 功能失败时当前页面可能只暴露底层模块错误。

**完成标准**

- 使用 Windows CI 或真实 Windows 机器构建安装包，不能复制 macOS 的 `node_modules` 产物。
- 完成本地模型下载、加载、索引和查询验收，并验证 WASM 降级。
- 启动时检查 PostgreSQL 客户端工具；缺失时提供安装路径选择或随包提供兼容工具。
- 所有平台错误转换为中文可操作提示，隐藏本机绝对路径和调用栈。

## 4. P1：功能已存在但闭环不完整

### FUNC-P1-001 项目工作项页只有列表，没有项目内多视图

**现状**

- 多维表格模块已具备看板、日历、甘特等视图。
- 项目详情“工作项”仍只显示单一列表，无法在项目上下文中切换视图、保存筛选或拖动状态。

**影响**

- 用户必须离开项目页进入多维表格，项目管理体验被割裂。

**完成标准**

- 项目工作项直接提供列表、看板、日历、甘特四视图。
- 复用同一任务数据，不创建镜像记录。
- 视图状态、筛选、分组和字段显隐可按项目保存。

### FUNC-P1-002 项目计划缺少基线、变更记录和关键路径

**现状**

- 已有项目周期、里程碑计划时间、任务依赖和进度计算。
- 没有“批准后的计划基线”、计划变更历史、偏差原因和关键路径计算。

**影响**

- 无法回答“当前延期是相对哪一版计划”“哪个节点会影响最终交付”。

**完成标准**

- 项目可生成只读计划基线快照。
- 后续日期变更记录变更前后值、原因和时间。
- 甘特图展示计划与实际偏差、关键路径和受影响节点。

### FUNC-P1-003 员工周报没有自动汇总为项目进展建议

**现状**

- 员工工作可关联项目/任务，已有团队和项目进展看板。
- 系统没有按项目自动整理“本周完成、下周计划、阻塞、风险、里程碑变化”，也不会生成可确认的项目进展草稿。

**影响**

- 主管仍需逐人阅读并手工写项目周进展，重复劳动较多。

**完成标准**

- 导入完成后按项目生成进展建议草稿。
- 草稿标明数据来源和未关联行，用户确认后才写入正式项目进展。
- 同一周期重复生成必须幂等；周报版本恢复后可重新生成。

### FUNC-P1-004 会议行动项与任务状态没有双向同步

**现状**

- 会议行动项可以幂等转任务并保存 `taskId`。
- 任务完成、取消或延期后，没有发现自动更新会议行动项状态和时间的逻辑。

**影响**

- 会议详情可能仍显示行动项未完成，而“我的工作”中的任务已经结束。

**完成标准**

- 行动项与任务建立明确的主从字段规则。
- 任务完成/取消同步行动项；行动项修改负责人或截止时间时提示是否同步任务。
- 会议页能直接看到最新任务状态和逾期情况。

### FUNC-P1-005 缺少跨对象统一活动时间线

**现状**

- 项目、员工、合作方等页面各有局部记录。
- 没有统一展示“任务变化、进展提交、风险处置、会议、文档、周报导入、提醒”的项目活动流。

**影响**

- 用户需要在多个页签之间反复寻找“最近发生了什么”。

**完成标准**

- 项目和员工详情均有统一活动流。
- 活动记录能回到原对象，并支持类型、时间和来源筛选。
- 自动操作与人工操作有明确标识。

### FUNC-P1-006 NOVA 历史会话和长对话没有分页

**现状**

- 会话列表一次性查询全部未归档会话。
- 打开会话时一次性读取全部消息。

**影响**

- 长期使用后，查询和前端渲染会越来越慢。

**证据**

- `backend/src/modules/workbench/knowledge/application/session.service.ts`
- `frontend/src/modules/knowledge/components/KnowledgeSessionList.tsx`

**完成标准**

- 会话列表采用游标分页和增量加载，置顶会话单独处理。
- 长对话只加载最近消息，向上滚动加载更早内容。
- 搜索结果仍能定位并打开目标会话。

### FUNC-P1-007 报表只有数据表和导出，缺少决策闭环

**现状**

- 已有项目组合、任务趋势、风险趋势、资源负荷和情报统计 API，以及 CSV/Excel 导出。
- 页面缺少趋势图、同比/环比、钻取、保存视图和定时生成。

**影响**

- 能看数据，但无法快速发现异常并进入对应项目、员工或风险。

**完成标准**

- 每个指标可钻取到组成明细。
- 支持本周/上周、本月/上月和自定义区间对比。
- 支持保存报表视图并生成周/月快照。

### FUNC-P1-008 备份恢复依赖工具未前置检查

**现状**

- 恢复预检会检查备份内容，但创建备份或恢复前没有统一的 `pg_dump`/`pg_restore` 可用性向导。

**影响**

- 用户可能在真正需要恢复时才发现本机工具缺失或版本不兼容。

**完成标准**

- 数据健康检查中常驻显示数据库客户端工具状态和版本。
- 手动备份前立即阻止不可执行任务，并给出修复方法。
- 提供一次可回滚的“恢复演练”，验证备份真正可用。

### FUNC-P1-009 知识索引失败缺少集中修复队列

**现状**

- 单个文件可以显示提取或索引失败，但没有统一的失败任务中心。

**影响**

- 文件数量增加后，用户很难发现哪些资料没有进入 NOVA 查询源。

**完成标准**

- 提供“索引健康”列表：未提取、未切分、未向量化、文件丢失、格式不支持。
- 支持按失败类型批量重试、忽略和查看原因。
- NOVA 回答范围明确排除未完成索引的文件，并提示数量。

## 7. 功能完成统一门槛

一个功能只有同时满足以下条件才可标记完成：

- 使用真实 PostgreSQL 数据，不使用演示数据代替。
- 前端、后端、数据库 migration 和对象关联都完成。
- 有加载、空数据、失败、重试和重复提交处理。
- 有单元/集成测试；关键流程有真实浏览器或 Electron 验收。
- Windows 相关功能必须在 Windows 产物中验收。
- 写操作有审计；删除或覆盖操作可恢复或有二次确认。
