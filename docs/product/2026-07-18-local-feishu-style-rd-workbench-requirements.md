# 本地飞书式研发项目与知识工作台：产品需求规格

**版本：** v1.0（重新收敛版）  
**产品形态：** Electron 本地桌面应用 + 本机 PostgreSQL  
**目标用户：** 单一研发主管/研发负责人  
**唯一产品目标：** 用项目、日常任务、会议、文档、知识库和多维表格，管理研发工作的全过程与沉淀。

> 本文替代旧需求清单中“按风险、合作方、申报、情报等后台菜单平铺”的产品组织方式。已有数据和 API 保留，但它们必须重新归入项目空间、文档知识或多维表格的上下文。

## 1. 产品原则

1. **先工作、后管理。** 打开应用先看到今天要处理的事，而不是数据表菜单。
2. **项目是中心。** 任务、会议、文档、文件、风险、决策与资料都能关联一个项目，并可从项目反向查看。
3. **一份数据，多种视图。** 项目、任务和会议不建立多套副本；表格、看板、日历、甘特只是同一数据源的不同呈现。
4. **文档是资产，不是附件说明。** 文档有正文、目录、版本、模板、标签与关联关系。
5. **本地优先、可恢复。** 数据、文件、提醒记录和备份都在本机；没有网络时核心工作不受影响。
6. **不做伪功能。** 未实现的能力不显示虚假数字或可点击但无结果的操作。

飞书项目以“空间、工作项、实例、流程、关联、视图”组织项目工作；本产品保留空间、工作项、关联与视图，去掉多人角色/权限/协同流程配置。[飞书项目核心功能](https://www.feishu.cn/content/4ek1avnv)

## 2. 主导航与信息架构

顶级导航只保留七个用户真实每天使用的入口：

```text
工作台 ｜ 我的工作 ｜ 项目 ｜ 文档与知识库 ｜ 多维表格 ｜ 日历 ｜ 搜索
```

| 入口 | 用户要解决的问题 | 主要内容 |
| --- | --- | --- |
| 工作台 | 今天最重要的是什么 | 今日任务、待提醒事项、近期会议、最近项目、最近文档、收藏、快捷新建 |
| 我的工作 | 我接下来要执行什么 | 收件箱、今日、本周、逾期、稍后处理、个人日历 |
| 项目 | 某个研发项目推进到哪里 | 项目空间、项目列表、模板、新建项目 |
| 文档与知识库 | 资料和经验在哪里 | 文档、文件夹、知识空间、模板、最近打开、收藏、回收站 |
| 多维表格 | 如何按结构化方式管理项目数据 | 项目、任务、会议、风险等预置表及自定义表、视图、字段、记录 |
| 日历 | 什么时候有任务、会议、面试或提醒 | 月/周/日视图、事件详情、新建日程、提醒 |
| 搜索 | 想找的内容在哪里 | 全局搜索与结果过滤 |

“会议”“风险”“问题”“决策”“合作方”“申报认定”“行业情报”不再占顶级菜单：它们是项目空间中的关联对象，或多维表格中的预置数据表。

## 3. 工作台

### 3.1 首页卡片

- **今日行动：** 今日到期、逾期、今天开始和手动置顶的任务。
- **待提醒：** 下一次提醒在 24 小时内的任务、会议和日程。
- **近期会议：** 未来 7 天的会议、面试和评审。
- **项目脉冲：** 最近访问项目、健康度异常项目、临近里程碑。
- **最近内容：** 最近打开/编辑的文档、会议纪要和知识页。
- **收藏：** 用户收藏的项目、视图、文档和多维表格。

每个卡片必须直接跳转到对应对象；无数据时显示可执行的新建入口。

### 3.2 全局操作

- 顶部固定：全局搜索、全局新建、通知中心、最近访问。
- 全局新建支持：项目、任务、日程/会议、文档、知识页、多维表格记录。
- 快捷键：`⌘K`/`Ctrl+K` 搜索，`⌘N`/`Ctrl+N` 打开新建菜单；键盘导航必须可用。

## 4. 项目空间

### 4.1 项目空间结构

进入一个项目后，保留固定项目上下文和项目标题。项目内导航为：

```text
概览 ｜ 工作项 ｜ 进展 ｜ 风险与问题 ｜ 会议 ｜ 文档与资料
```

| 页签 | 必须展示 | 必须操作 |
| --- | --- | --- |
| 概览 | 项目目标、负责人、状态、健康度、里程碑、临近任务、最近进展 | 编辑项目、创建任务/会议/文档/进展 |
| 工作项 | 关联任务的表格、看板、日历、甘特视图 | 新建、编辑、完成、延期、设提醒、关联事项 |
| 进展 | 进展记录、完成百分比、阻塞项、时间线 | 提交进展、查看历史 |
| 风险与问题 | 风险、问题、决策及其状态、负责人、关联任务 | 新建、处置、关闭、创建跟进任务 |
| 会议 | 项目会议、议程、纪要、行动项 | 新建会议、写纪要、行动项转任务 |
| 文档与资料 | 项目文档、知识页、附件、材料版本 | 新建/关联文档、上传文件、查看版本 |

### 4.2 项目工作项

- 首批固定工作项：任务、风险、问题、决策、会议；后续可增加申报、情报和非项目研发记录。
- 每个工作项至少包含标题、状态、优先级、负责人、开始/截止时间、项目关联、描述、创建/更新时间。
- 关联关系必须双向可见：例如从风险可查看关联项目和跟进任务，从任务可查看来源风险/会议行动项。
- 不实现飞书的多人角色、流程管理员、跨空间同步；本地单人只保留状态流和字段校验。

飞书项目使用工作项关联、筛选、分组、排序与多种视图组织同一项目数据；本地版采用相同的工作组织方式，但不引入协同/权限配置。[飞书项目平台介绍](https://www.feishu.cn/content/1afedyby)

## 5. 我的工作、日历与提醒

### 5.1 我的工作

固定视图：收件箱、今日、本周、逾期、稍后处理、已完成。

- 收件箱显示尚未分类处理的任务、会议行动项和手动创建事项。
- 今日/本周按任务截止日、开始日和日程时间过滤。
- 稍后处理给任务一个恢复日期；恢复前不在今日/本周干扰用户。
- 完成任务时更新项目、日历、多维表格和工作台中的同一条记录。

### 5.2 日历

- 月、周、日三种视图；同一日历数据源包含任务截止日、会议、面试、评审与提醒。
- 创建“面试”时作为 `CalendarEvent` 保存，可关联项目、文档或候选资料；字段包括主题、开始/结束时间、地点/链接、备注、提醒规则。
- 点击日程进入详情，可编辑、取消、复制或打开关联会议纪要。
- 首期不实现外部 Google/Outlook/Apple 日历同步，也不实现多人邀约。

### 5.3 通知与提醒

提醒是独立的本地能力，所有任务、会议、日程和面试共用。

```text
对象时间 + 提醒规则 → 本地提醒服务 → 通知记录
                                      ├─ 页面实时提醒
                                      ├─ Electron 桌面系统通知
                                      └─ 短信通道（重要事项，可配置）
```

- 提醒规则支持到点、提前 N 分钟/小时/天，以及自定义多个提醒点。
- 后端调度服务定期扫描 PostgreSQL；到点后持久化 `Notification`，通过 WebSocket 推送到已打开前端。
- 前端收不到 WebSocket 时，通知中心从未读 `Notification` 补偿读取；用户可读、稍后提醒、关闭。
- Electron 保持后台/托盘运行时，使用系统原生通知；应用完全退出时不保证通知送达，设置中应明确说明。
- 短信仅用于标记为“重要”的面试、关键会议和关键任务；短信发送需要用户后续配置服务商、手机号、签名/模板、网络与费用，失败必须记录且不能阻塞本地提醒。
- 不做未经配置的短信发送，不保存明文服务商密钥；密钥保存在本地受保护配置中。

飞书日历也将日程更新和会议相关提醒作为日历助手能力；本地版采用同样的提醒概念，但通知目标仅为当前本机用户。[飞书日历助手](https://www.feishu.cn/hc/zh-CN/articles/049951025910-%E6%97%A5%E5%8E%86%E5%8A%A9%E6%89%8B%E4%BB%8B%E7%BB%8D)

## 6. 会议与会议纪要

- 会议由日程创建，也可独立创建；字段包括主题、时间、地点/链接、项目、参与说明、议程、纪要、行动项、决策、附件和关联文档。
- 会议纪要是可编辑的本地富文本文档，自动与会议关联。
- 行动项可逐条创建任务，必须记录 `sourceType=MEETING_ACTION` 和 `sourceId`；重复转换时展示已有任务，不重复创建。
- 决策可由会议创建，包含结论、背景、影响、决策日期和后续任务。
- 会议可以是“面试”“评审”“项目例会”“外部沟通”等类型；类型影响模板和默认提醒，不改变底层关联机制。

## 7. 文档、文件与知识库

### 7.1 文档

- 文档支持：标题、段落、标题层级、列表、任务清单、表格、引用、代码块、链接、图片和附件引用。
- 文档自动保存，用户可显式“保存为版本”；版本只读，可查看、恢复、下载/导出。
- 模板至少包括：项目计划、会议纪要、周报、项目复盘、技术方案、面试记录。
- 文档可关联项目、任务、会议、风险、知识页和多维表格记录。

### 7.2 文件

- 文件夹、上传、下载、重命名、移动、版本上传、回收站、恢复、永久删除。
- 文件元数据必须记录文件名、MIME、大小、校验和、创建时间、版本与对象关联。
- 本地文件存储路径由设置页管理；文件缺失时显示修复状态，不返回损坏下载。
- 文件版本遵循“同一文件标识，多版本内容”的原则；飞书云文档同样支持在保持链接不变的前提下管理上传文件版本。[飞书文件版本管理](https://www.feishu.cn/hc/zh-CN/articles/360049067469-%E5%A6%82%E4%BD%95%E6%9F%A5%E7%9C%8B%E5%92%8C%E6%9B%B4%E6%96%B0%E6%96%87%E4%BB%B6%E7%9A%84%E7%89%88%E6%9C%AC?slug=true)

### 7.3 知识库

- 知识空间、目录树、知识页列表、正文编辑、标签、模板、收藏、最近访问、归档与回收站。
- 知识页可由项目复盘、会议纪要或普通文档转入；转入后保留来源关系。
- 搜索支持标题、正文、标签和关联对象；结果显示摘要、命中位置、所属目录和关联项目。
- 从项目、会议、任务或文件详情可看到“关联知识”，从知识页可看到反向关联对象。
- 第一版不做多人实时协同、评论、文档权限共享或云端同步。

## 8. 多维表格

多维表格是一个真正的产品模块，不是旧业务页面的集合。

### 8.1 首批预置表

- 项目总表
- 工作项总表（任务、风险、问题、决策可按类型筛选）
- 会议与行动项表
- 文档与知识资产表
- 项目风险与决策表

### 8.2 自定义表

- 用户可创建数据表、字段和记录。
- 首批字段：文本、多行文本、数字、日期时间、单选、多选、复选、链接、附件、关联记录、查找引用、公式、创建/更新时间。
- 关联记录支持单向/双向关联；查找引用展示关联表字段；公式按字段对所有记录计算。
- 预置表和自定义表均支持导入/导出 CSV、Excel。

### 8.3 视图

- 表格视图：字段列、筛选、排序、分组、冻结主字段、行内编辑。
- 看板视图：按单选状态字段分组，卡片拖动更新该字段。
- 日历视图：按日期字段显示记录。
- 甘特视图：按开始/结束日期或日期+时长显示记录。
- 表单视图：根据字段生成本地数据录入表单。
- 画册视图：按附件字段显示卡片。

任一视图修改一条记录，都必须同步反映在其他视图。飞书多维表格同样将表格、看板、日历、画册、甘特和表单作为同一数据源的视图。[飞书多维表格视图](https://www.feishu.cn/hc/zh-CN/articles/360049067931-%E4%BD%BF%E7%94%A8%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC%E8%A7%86%E5%9B%BE)

## 9. 全局搜索、数据治理与安全

- `⌘K`/`Ctrl+K` 搜索项目、工作项、会议、日程、文档、知识页、文件和多维表格记录；支持类型、项目、时间、状态过滤。
- 搜索索引必须来自本地 PostgreSQL 和本地文件元数据；不上传内容到外部服务。
- 导入先预检并显示错误行；导出可选当前视图/当前表/完整数据。
- 每日可自动生成本地备份；手动备份包含数据库、文件 manifest、版本和校验和。
- 恢复前验证 schema、hash、文件路径和存储空间；恢复失败自动回滚到恢复前快照。
- 审计记录创建、编辑、删除、恢复、导入、导出、备份、恢复和通知发送结果。
- 回收站保留对象与文件关联，恢复后保持原引用；永久删除需明确确认。

## 10. 现有功能的归位

| 已有模块 | 新位置 |
| --- | --- |
| 项目、里程碑、任务、进展、健康度 | 项目空间 + 我的工作 + 多维表格 |
| 风险、问题、决策 | 项目空间“风险与问题” + 风险决策表 |
| 会议、议程、行动项 | 项目空间会议 + 日历 + 会议行动项表 |
| 申报认定 | 项目空间可选工作项 + 多维表格扩展表 |
| 合作方、沟通 | 项目关联对象 + 自定义/预置多维表 |
| 行业情报 | 后续作为“情报卡”工作项，能转任务/风险/会议 |
| 报表、资源负荷 | 多维表格仪表盘和项目组合视图，后续阶段实现 |

## 11. 明确不在本地单人版范围

- 聊天、群组、消息流、联系人、组织架构、权限、审批、考勤、邮箱、视频会议。
- 多人实时协同编辑、评论、@提及、在线状态、共享链接和冲突处理。
- 飞书、Google、Outlook、Apple 日历/云盘的双向同步。
- 未配置短信服务商时的真实短信发送；AI 自动摘要、联网采集和外部系统集成进入后续独立阶段。

## 12. 实施顺序与完成定义

1. **项目空间、我的工作、日历和通知。**
2. **文档、会议纪要、文件与知识库。**
3. **多维表格与预置表。**
4. **全局搜索、导入导出、备份审计。**
5. **行业情报、资源报表、短信服务商、Electron 打包。**

一个功能只有同时满足以下条件才算完成：前端可操作、后端 API 可持久化、数据库迁移已部署、加载/空/失败状态完整、自动化测试通过、实际本机数据能在关联页面与搜索/视图中正确出现。
