## 2026-06-23

- 继续补完第一版未闭合的“真正微服务”能力。
- 新增 Prisma JobRepository 与 GeneratedFileRepository，实现 API/Worker 之间共享任务状态和文件元数据。
- JobsModule 支持生产/配置 `DATABASE_URL` 时使用 Prisma，测试或无数据库时自动回退内存实现。
- PlatformPrismaService 改为只在缺少 `DATABASE_URL` 时跳过数据库连接，`NODE_ENV=local` 配置数据库时也可以跑真实持久化。
- Worker 引入 JobsModule，处理任务时回写 `processing`、`succeeded`、`failed` 状态。
- Worker 生成 Excel 与换发型 SVG 后写入 Storage，并创建 GeneratedFile 元数据。
- 新增 `/api/files/:fileId/download` 文件下载接口。
- 补齐旧接口兼容层：`/api/export`、`/api/export-batch`、`/api/hairstyle/transform`，旧版 `merged_cells` 会转换成新合同 `mergedCells`。
- 修复 OcrToolsModule 未显式导入 QueueInfrastructureModule 导致 `OcrJobProducer` 静默 no-op 的问题。
- docker-compose 增加 Postgres，package scripts 增加 `dev:infra`、`prisma:push`。
- 本机 Postgres 创建 `backend_core_platform` 数据库，并执行 `DATABASE_URL=... pnpm prisma:push` 同步 schema。
- 使用同一个 Postgres + Redis 启动 API Gateway 与 OCR Worker：
  - API：`NODE_ENV=local PORT=3000 DATABASE_URL=... REDIS_HOST=127.0.0.1 REDIS_PORT=6379 QUEUE_PREFIX=backend-core-platform LOCAL_STORAGE_ROOT=var/storage pnpm start:dev:api`
  - Worker：`NODE_ENV=local DATABASE_URL=... REDIS_HOST=127.0.0.1 REDIS_PORT=6379 QUEUE_PREFIX=backend-core-platform LOCAL_STORAGE_ROOT=var/storage OCR_WORKER_CONCURRENCY=2 pnpm start:dev:ocr-worker`
- HTTP 联调通过：
  - `/api/export` 返回 `202 + jobId`，任务从 `processing` 到 `succeeded`，`/api/files/:fileId/download` 成功下载 xlsx。
  - `/api/hairstyle/transform` 返回 `202 + jobId`，任务从 `processing` 到 `succeeded`，下载接口成功返回 SVG。
- 最终验证通过：
  - `pnpm test:unit`：20 suites，41 tests。
  - `pnpm test:integration`：4 suites，8 tests。
  - `pnpm test:e2e`：2 suites，10 tests。
  - `pnpm lint` 通过。
  - `pnpm build` 通过。
